### 7 · Header strip font — off-feel

> "The fonts of 'KAI'S FLOW · WED, JUL 08 · SYNCED' (circled in red) isn't really coherent with the rest of the website's feel."

Screen: the top strip `AppLayout` renders above every page (mono uppercase tracked). It follows the system's mono-metadata idiom, but it's the only full-width mono strip in the app and sits directly over the serif display headings — Kai reads the combination as incoherent. **→ UX-retrofit step 16a** — reconcile against the Today comp's header treatment (`design/Today v3.dc.html`); the fix may be sizing/weight/placement rather than a font swap, build-session judgment per DESIGN_SYSTEM.

### 8 · Voice Capture button — minimal + floaty, all pages

> "The Voice Capture button (circled in green) needs to be a bit more minimal and more floaty across all the pages of the website."

Current state (found): `VoiceCaptureButton` is a large terra pill rendered in exactly two page headers (Today, Inbox) — not floating, not global. **→ UX-retrofit step 16b** — one floating, minimal capture affordance in `AppLayout` (all pages). Note the one-terra-CTA-per-view rule: a floating mic on every page can't stay terra without fighting each page's own CTA — "minimal" per Kai's own word. Sequencing: step 12f (mic silent no-op repair) touches the same component — repair first or together.

### 9 · Terrarium captions blurry

> "For some reason some of the texts (the texts below the name of each flower, highlighted in yellow) aren't sharp and are kinda blurry which isn't the best for their visibility."

**Root cause (found, `Terrarium.tsx:196`):** each plant cell div carries `transform: rotate(±0.5–0.8deg)` and the caption text (8.5px mono label + 15px hand note) renders *inside* that rotated div, on top of the section's own `rotate(-0.25deg)` — small text rotated off the pixel grid rasterizes blurry. Fix: move the per-plant rotation onto the `<img>` only (its `transformOrigin` is already set for exactly this), leave the text column unrotated. **→ UX-retrofit step 12i** (it's a rendering defect — rides the repair batch).

### 10 · Washi-tape stickers drift off the flowers at different zooms

> "Most of the sticker looking elements that are on top of the flowers are not relative to them, i.e. when in different zoom presets they move in a different way from the flowers, I need them to be together always."

**Root cause (found, `Terrarium.tsx:210–223`):** each tape `<span>` is absolutely positioned with hardcoded px `top`/`left` (+ `marginLeft: -20`) relative to the *cell*, whose width is fluid (`repeat(6, 1fr)` grid / responsive flex) — the centered image shifts as cell width changes (zoom, viewport) but the tape's px offsets don't track it. Fix: wrap the `<img>` in a shrink-wrapped `position: relative` inline wrapper and anchor the tape inside *that*, so offsets are relative to the image box itself. The section-corner tapes are anchored to the section and don't drift — only the per-plant ones. **→ UX-retrofit step 12j.**

### 11 · Tasks page layout — org panels left, tasks take the space, filters

> "I think that the 3 sticky notes for the 'domains', 'areas' and 'projects' should be on the left (ordered by which stems from who) and to leave room for the actual tasks to take the majority of the space by the page, also there should be filters in the tasks view by open, completed and all and then of course the project filtering."

Screen: `tasks-page.png` — the Domains/Areas/Projects sticky-note panels currently sit in a 2-col grid *above* the task list, pushing tasks below the fold. **→ UX-retrofit step 16c** — org panels become a left rail on the default `/tasks` view ordered by hierarchy (Domains → Areas → Projects), task list gets the majority width; add a filter row: **open / completed / all** + filter-by-project. Overlap handled: the "completed" filter state **absorbs step 13's planned collapsed Completed section** (one surface, not two — search deep-links for done tasks land on the completed filter). Consult `design/Tasks.dc.html` before building. Smart-list views already hide the org panels — default view only.
