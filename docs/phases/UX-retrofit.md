# UX Retrofit — Akiflow Core (smart lists, durations, keyboard, planning)

**Parity rows:** 52–57 pulled forward from P6/P8 (smart lists · Someday · keyboard map · bulk actions · month/planning views) + the duration/metadata/snooze gaps found in the 2026-07-08 audit · **Status:** see `../ROADMAP.md`

> Like the Areas retrofit, this is not a numbered phase — it is **interaction debt against the whole app**. The 2026-07-08 audit's core finding: the parity matrix tracked feature *nouns* (inbox ✓, command bar ✓, time-blocking ✓) while Akiflow's actual value is interaction *verbs* — duration on every row, overdue grouping with age, time-scoped smart lists, one-keystroke triage, keyboard-first everything. None of those were matrix rows, so none got built. This phase builds exactly that fabric, before any new breadth (P6/P7) is added.
>
> **UI rule:** none of these surfaces has a mockup. Every screen/element here is built directly from `docs/DESIGN_SYSTEM.md` (the recipe in §4) + `design/SKILL.md` + P-DESIGN §3–§4. That is the intended path — no mockups get made for post-export screens.

## Goal

Open the app and plan a day the way Akiflow allows: every task shows its duration/project/age at a glance, the sidebar answers "what's today / this week / upcoming / someday", overdue work confronts you grouped and age-sorted, triage and planning run entirely from the keyboard, and the calendar respects task durations. Success is a stopwatch test, not a feature list: **capture 5 tasks, triage the inbox, and time-block tomorrow — keyboard only, under 3 minutes.**

## Pitfalls

- **Don't build five pages.** Smart lists are one TasksPage + one grouping function + a query param. If a second task-list component appears, stop and reuse.
- The grouping engine must use the app's timezone convention (store UTC, render Africa/Cairo) — "today" boundaries are Cairo midnight, not UTC. Test the 23:00 edge.
- `someday` interacts with Slipping and smart-list counts — exclude it everywhere a "pending task" is counted, or Someday becomes guilt with extra steps.
- Keyboard focus ring vs. browser focus: use a real roving tabindex (accessibility), not a CSS-only highlight — screen readers and the `?` overlay should agree with reality.
- Escape-stack: command bar, search, snooze menu, context menu, bulk bar can now nest — one overlay manager order (topmost closes first), not five competing listeners.
- Resize-writes-duration is a two-way binding — guard against loops (only write when the event is task-linked and the value actually changed).
- Bulk actions loop outbox writes — fine at personal scale; don't build a batch API for it. `// ponytail: N sequential outbox writes, batch RPC if bulk >100 ever happens`
