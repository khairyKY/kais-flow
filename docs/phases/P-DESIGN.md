## 2. Hard rules (the anti-drift contract)

- **Never write a hex color.** Every color in app code is `var(--token)`. The mockups are hex-baked — translate via §3. If a mockup hex isn't in §3, find the nearest token; if genuinely none fits, stop and leave a note for Kai.
- **New code uses semantic tokens** (`--text-primary`, `--bg-surface`, `--acc-*`, `--line-*`), not the deprecated legacy aliases. When you touch a file, migrate its legacy aliases in passing.
- **Skin only.** No logic edits, no new deps, no new routes, no schema. If a mockup shows data the feature doesn't have, render what exists and note the gap in §8.
- **One screen per session.** Finish its checklist (§7) before touching another.
- **Respect phase discipline:** only re-skin screens whose feature is live (see §5). Mockups for unbuilt features wait for their feature phase.
- Radius: cards `--radius-sharp` (3px), inputs `--radius-md`, nav links `--radius-input`, buttons `--radius-pill`. Nothing else.
- Type: display = Source Serif 4 at 500/600 (never bold+huge), body = Inter Tight 14.5px, metadata = IBM Plex Mono uppercase tracked (`--ls-mono`), Caveat = one marginalia per card max, never in buttons/labels.
- Color: one `--acc-terra` CTA per view; one gold Goal-of-Day card per view; each surface keeps its own accent flower color (§4); overdue = terra; everything else muted mono.
- Decorations: tiny card tilts from `--tilt-*`; washi tape only on placed cards, never on list items; drop-shadow `--shadow-drop-sm` on flower PNGs; no fireflies in light mode.
- Mockups are 1440×1024 desktop. They define desktop; **keep the app's existing responsive/mobile behavior** and apply the same tokens/type there.

### 5.1 Calendar (A5) — interaction states are part of the skin

The mockup is static; the live screen is not. P3 already shipped the full Akiflow-style interaction set, and the skin must style **every one of these states without breaking them**:

| Interaction (already working)          | What to style                                                                                                                                                                                 |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Drag task from Unscheduled rail → grid | rail chips (parchment card, grab cursor, mono "drag to block · 30 min" caption per mockup), the FullCalendar drag mirror (`.fc-event-mirror`), drop-target column highlight (`.fc-highlight`) |
| Drag empty slot → new event            | selection ghost (`.fc-highlight` / mirror) — use `--acc-lavender` at low opacity, dashed `--line-dashed` outline                                                                              |
| Move event (drag)                      | dragging chip elevation `--shadow-card`, slight tilt is fine; settled chip returns flat                                                                                                       |
| Resize event (edge handle)             | `.fc-event-resizer` visible affordance on hover (thin `--line-solid` grip), never hidden                                                                                                      |
| Now indicator                          | `.fc-timegrid-now-indicator-line/-arrow` → `--acc-terra`, 1px                                                                                                                                 |
| Event chips                            | parchment `--bg-surface`, 3px radius, 3px left rail in `--acc-lavender` (task-linked blocks) vs `--line-solid` (plain blocks), mono time caption                                              |
| Event click                            | currently a delete-confirm; keep it wired — the Event Details panel replaces it in C6, not in this pass                                                                                       |

Rules: restyle via `CalendarGrid.css` + CSS variable overrides on FullCalendar's `.fc-*` classes only. **Do not fork/replace `CalendarGrid.tsx`** — its props are the contract. Do not change slot duration, snap, or the 30-min default drop length. After skinning, manually verify all five interactions (external drop, select-create, move, resize, click-delete) still persist correctly — that's the A5 behavior check in §7.

## 6. Per-screen workflow (repeat every session)

1. Read `design/SKILL.md` (once per session) and open `design/<Screen>.dc.html` — render it in a browser if you can, otherwise read the markup.
2. Read the screen's block in `SCREENS.md` / `SCREENS-PART-TWO.md` for component/route names.
3. Re-skin the existing components in place. Reuse the component vocabulary (§1.4); if two screens need the same visual (SectionLabel, tape strip, flower badge), extract one shared component into `app/src/components/` the second time it appears — not the first.
4. Translate every color via §3. Copy structure/spacing from the mockup using `--sp-*` / `--gap-*` / `--pad-card*` tokens.
5. Run the checklist (§7). Show evidence.
6. Append one line to §8 (screen, date, deviations).

## 7. Acceptance checklist (per screen)

- [ ] `cd app && npm run build` passes.
- [ ] No new hex literals: `grep -rnE "#[0-9a-fA-F]{3,6}\b" app/src/features/<feature>/` returns only pre-existing/allowed ones (§3).
- [ ] Touched files use semantic tokens, zero legacy aliases remain in them.
- [ ] Screen matches mockup at 1440px (side-by-side screenshot or preview check).
- [ ] Mobile layout still works (no horizontal scroll at 375px).
- [ ] Set `data-theme="night"` on `<body>` manually: screen stays readable (full night scene only required after step D).
- [ ] Behavior unchanged: the screen's existing interactions still work (complete a task, file an inbox item, etc.).
- [ ] SKILL.md audit: ≤4 SectionLabels, exactly ≤1 terra CTA, ≤1 gold card, no tape on list items, no pure white/black.
