## What it does now
- **Open a draft.** Desktop: click an empty slot (an hour from the quarter you hit) or drag a range (exactly what you dragged, a quarter stays a quarter). The all-day band works the same (drag over two days = a two-day draft). Phone: tap a slot, an hour, snapped to the quarter, slid up if it would run past 24:00. A block appears right there with the caret in its title and, beside the time, the kind it will be ("14:00-15:00 · Event").
- **Settle it.** Enter saves. Esc (and Android Back) discards. A press anywhere else saves when there is a title and discards when there isn't, and that press never opens the next draft. **Enter on an empty title waits** (Kai 2026-10-21: no "Untitled" ever).
- **Kind.** An event. A leading `t ` or a trailing `task` makes a task, a trailing `block` a Time block; the draft's kind label changes as you type. A task goes through the command bar's own parse (`parseCommand` + `quickAddTask`: `!!`, `#project`, `*label`, `every week`, `// notes`, link) but the **slot places it** (due and blocked on that hour, its length the slot's), then `toastAdded`. Right-click's "New Event / New Time Block" and Ctrl-click (task) open a draft with that kind preset.
- **Taps for a 1-hour event: tap, type, Enter** (harness counts 1 tap + Enter on both viewports; the old phone path was 4 taps).
- **Undo.** Event: "Added · title" with Undo (the app-wide history too, so Ctrl+Z). Task: the capture toast and Undo, its block with it.
- **Offline.** Same outbox writes; the block shows at once and the row is sent when the network is back (harness `o`).
- **Details.** Only by clicking the saved block: the existing popover (desktop) / sheet (phone), untouched.
- **Phone keyboard.** The draft is opened inside the tap (`flushSync`) so its field is focused in the click's own task: the harness hooks `HTMLElement.focus` and asserts `inClick` + transient user activation (the capture-type handoff's 2026-10-07 condition: iOS and the Android WebView raise the keyboard for nothing later). The field is 16px (iOS doesn't zoom) and the grid scrolls the slot to the top (`SHEET_LEAD`), so it sits clear above a 300px keyboard. A real iPhone still needs a look.
- **Colour.** Default logic only (`color: null`; a task its Iris, an event its Rose, as before).

## How
- `calendar/createDraft.ts`: the state machine (zustand store `useDraft`, `readTitle`, `settle`, `tapSpan`, `saveDraft`, `finishDraft`, the swallowed-press flag). One store for both grids.
- `calendar/DraftTitle.tsx`: the input + time/kind line, the Enter/Esc/outside-press handling, `MirrorBody` and `AllDayDraft`.
- Desktop: the draft is typed **in FullCalendar's own selection mirror** (`eventContent` of the id-less mirror → `MirrorBody`; no overlay hack, it positions and overlaps like a block). A click's quarter is widened by `select()` to the hour (`CalendarGridHandle.select`). The all-day band has no mirror (FullCalendar draws only a highlight there), so `AllDayDraft` types over that highlight. Keys are caught by a native listener on the input, because FullCalendar's own block key handling (Space/Enter click the block) otherwise ate spaces.
- Phone: `PhoneGrid` draws the draft as a `.pc-block.pc-draft` in the kind's hue (through the existing `look`).
- The rail's / planning panel's "Quick add task…" now opens the capture bar as a task (`openTaskCapture`), since the popover it used to open is gone.
