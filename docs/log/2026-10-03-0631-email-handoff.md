# Email confirmation, shippable at $0: screens, branded emails, Gmail SMTP

Branch `claude/email`, cut from `origin/claude/decisions` (048c6c5). Not merged, not deployed. Files changed are in `features/auth/`, `supabase/templates/` (new), `supabase/config.toml`, `.github/workflows/release.yml`, `docs/EMAIL.md` (new) and the first-run harness. App.tsx, onboarding and the shared components are untouched.

**Confirm email is still off.** `enable_confirmations = false` stays in `config.toml`; nothing changes on the live project until Kai adds the two SMTP secrets and a release runs. Until then sign-up behaves exactly as today.

## What changed

- **9c–9f switch on by themselves** (`SignInPage`, `AuthLayout`):
  - `signUp` with a session (confirmation off, today) → "/" → onboarding, as before.
  - `signUp` with no session (confirmation on) → **9c Check your email**: sealed envelope, "We sent a link to **email**. Open it on this phone and you're in — no need to sign in again." ("this device" on desktop), "Waiting for the link…", Open email app when the inbox is known (otherwise Resend is the one CTA), "Wrong address? Change it" (→ 9a, fields kept), "Not there? Check Spam or Promotions."
  - **9d Resend cooling down:** Resend counts down 60s in its own label from the first arrival and again after each send ("Resend in 0:48"), then reads "Resend link". A send toasts "Sent a new link to email" (plain toast, no Undo). A 429 reads as sent, like the reset request.
  - **"Waiting for the link…" is true.** A link opened in the same browser signs the waiting tab in through supabase-js's broadcast, and it plays 9f. A link opened where the tab can't hear it (the Gmail app's own browser, the website from the Android shell) is caught on the way back: when the tab becomes visible again it tries the password once, quietly. Not confirmed yet → that just fails, nothing shows.
  - **9f Email confirmed ✿:** the link's `emailRedirectTo` is still "/" (already allow-listed). At boot `recovery.ts` re-points a `type=signup` link to `/sign-in?confirmed` (the hash rides along, like reset links → `/reset`). No wordmark; the two broken seal halves fall open either side of the seedling; "Signing you in…"; "welcome to the garden"; a sage line fills to the drawn 62% while signing in, then the rest. About 1.2s after the session arrives it goes to "/" → OnboardingGate → `/onboarding` (9g). Reduced motion: no animation.
  - **9e This link has expired:** a used or expired link outside `/reset` (GoTrue's `#error=…&error_code=otp_expired`) is re-pointed to `/sign-in?expired`. Envelope back, "Links last an hour and work once. We'll send a fresh one to email." **Send a new link** resends to the address this device knows → 9d with its toast; **Use a different email** → 9a with the address kept. Confirmation tokens that don't hold (the server refuses them) also land here. `/reset` keeps its own 9k-3.
- **Pure logic, tested** (`authLogic.ts`):
  - `readAuthRedirect` reads `type=signup` + tokens as `confirmed` (it was `none`).
  - `authLinkLanding(redirect, path)`: where an email link must land before the router reads the address.
  - `signUpOutcome(data)`: `in-use` (no identities) / `check-email` (no session) / `signed-in`.
  - `signInView(...)`: `confirmed` / `in` / `expired` / `check-email` / `form`.
  - `resendLabel(until, now)` + `RESEND_WAIT_MS`.
- **Reuse:** `ResetSent` (9k-1) and the new `CheckEmail` (9c/9d) share one `LinkSent` body; `resendConfirmation` sits next to `requestReset` in `recovery.ts` and reuses `resetRequestLooksSent`.
- **Art:** `ds/assets/seal/broken-left.png` / `broken-right.png` from `design-export/ds/assets`, slimmed like the other first-run art (PIL quantize 256 FASTOCTREE, 200px tall, 11 KB + 12 KB).
- **Branded auth emails** (`supabase/templates/`): confirmation, recovery, magic_link, email_change, invite, plus the password-changed and email-changed security notices (CLI 2.118.0 supports notifications; phone/identity/MFA ones skipped — those features don't exist here; reauthentication skipped — `secure_password_change` is off).
  - Tables + inline styles, 600 max, linen `#EFE9DB` page, parchment `#FBF6E9` card with a `#e0d8c2` hairline, bark `#2a2420` heading, muted `#5f5849` body, terra-ink `#9C5139` pill button with parchment text, lavender-deep `#6a5988` fallback link — all from `styles/tokens/colors.css`.
  - Source Serif 4 → Georgia for headings, Inter Tight → system sans for text. The K icon is `https://kais-flow.kaidagoat.workers.dev/icon-192.png` at 32px next to a text wordmark.
  - A `prefers-color-scheme: dark` block uses the night tokens (Apple Mail / iOS Mail); clients that invert on their own get solid `bgcolor`s to invert.
  - Each link email has a "Button not working?" plain link. The notices link to `/sign-in?forgot` ("It wasn't me — reset it") or ask for a reply.
- **SMTP in config, secret-free** (`config.toml`): `[auth.email.smtp]` on, `smtp.gmail.com:587`, `user`/`admin_email = env(SMTP_USER)`, `pass = env(SMTP_PASS)`, sender "Kai's Flow"; the five templates and two notices wired (`content_path`: templates from the repo root, notices from `supabase/` — the CLI resolves them differently); `[auth.rate_limit] email_sent = 60`. Checked against the CLI source: with the env vars unset the CLI keeps `env(…)` literally and only warns, so `supabase link` / `db push` / `functions deploy` in the release still load the file.
- **Release step, not `config push`** (`release.yml`, "Auth email", after the live check): when `SMTP_USER` and `SMTP_PASS` secrets both exist it reads `config.toml` (Python `tomllib`) and PATCHes `/v1/projects/{ref}/config/auth` with only: `smtp_*`, `rate_limit_email_sent`, `mailer_subjects_*` / `mailer_templates_*_content`, `mailer_notifications_*_enabled`, and `mailer_autoconfirm = !enable_confirmations`. Without the secrets it writes one summary line and does nothing. The password is never printed; on a refusal only the API's error message is.
  - **Why not `supabase config push`:** in CLI 2.118.0 (`pkg/config/updater.go`, `auth.go` `ToUpdateAuthConfigBody`) it sends the whole auth block — `site_url`, `uri_allow_list`, `password_min_length`, JWT expiry, every rate limit, providers, MFA — plus API, DB and storage settings. Our `config.toml` carries local-dev values there (`site_url = "http://127.0.0.1:3000"`, minimum 6), so one push would break every email link on the live project. Same endpoint, narrower body.
  - **Switching Confirm email on** = set `enable_confirmations = true` in `config.toml` and release. Once the secrets exist, `config.toml` wins over the dashboard toggle at every release.
- **Kai's steps:** `docs/EMAIL.md` — 5 steps: pick the Gmail account, 2-Step Verification, App Password, two GitHub secrets, tell Claude "SMTP is in". Then a reset-email test, then the flip.

## Risks / not done

- **Not tried against the live project.** No secrets exist yet, so the PATCH has not run; field names and types were checked against the CLI's generated API types, not by a live call. The first release with secrets is the real test; its failure path prints only the API's message.
- **Gmail may refuse the first send** if the account is brand new or Google flags the sign-in; the fix is in the Gmail account's security alerts. Daily cap about 500.
- **Link scanners** in some work inboxes open links first and use them up → 9e. The template docs' fix (a code instead of a link) needs a code-entry screen; not built.
- **The broadcast handoff** still depends on supabase-js's BroadcastChannel (same browser only); the come-back retry covers the rest only while the tab still holds the typed password (a reloaded 9c tab falls back to sign in, where "Email not confirmed" shows the existing calm line).
- **The two-tab check flaked early on:** in 2 of 5 full runs (the 2nd and 3rd) the waiting tab played 9f but then stayed on "/" instead of reaching /onboarding (once day, once desktop). The last 2 full runs passed 407/407 and an isolated loop passed 4/4. It looks like the dev server's cold compiles the harness memo warns about, but that isn't proven; the check now prints the page's text and errors if it fails again.
- **`enable_confirmations` lives in `config.toml`:** once the secrets exist, a dashboard toggle is reset at the next release.
- No `docs/log/INDEX.md` line and no ROADMAP edit (parallel builders; the conductor adds them).
