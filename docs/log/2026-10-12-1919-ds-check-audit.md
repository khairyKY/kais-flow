
**How the gate works.** The existing drift sits in the baseline. CI fails only when a hit is not already there. The baseline matches on the line's text, not its line number, so moving code around does not trip it. Copying an old drifting line into a new place does trip it (the count goes up). I checked this by adding `{ color: "#333", fontSize: 11, borderRadius: 16 }` to a file: the run reported 3 new hits and exited 1. With the line removed it exited 0.

**Allowing a deliberate exception.** Put `// ds-ok: <reason>` on the line, or in the comment block directly above it. CSS uses `/* ds-ok: <reason> */` and JSX uses `{/* ds-ok: <reason> */}`. A reason is required: a bare `ds-ok:` does not count. The existing `deviation(<date> …)` markers count as accepted too, per CONDUCTOR's rule "Kai's eyes > export > code". 7 hits are accepted this way today.

## What the checker cannot see (keep it in human review)

These need runtime layout or intent, so a regex would only produce noise:

- One terra CTA per view. `Button` defaults to `variant="cta"`, so a count per file means nothing.
- 48 × 48 hit targets, because the hit area comes from padding and pseudo-elements.
- Every gesture has a ⋯ tap path.
- At most one Caveat line per card.
- Metadata is always mono + uppercase + tracked.
- Motion respects the Botanical animations setting.
- Icon stroke 1.6 and two icon families only.
- Copy and voice.

The Overlays "Confirm · destructive only" card is honoured: a ConfirmCard that says *permanently / for good / can't be undone* is not flagged. That is why the Inbox purge, the photo removal and sign-out pass.

## Checker ceilings (so nobody over-trusts it)

- **It uses regex and a small tokenizer, not a TS/CSS parser.** Style values built in variables or helper functions are invisible to it, unless they are `CSSProperties` object literals using the usual keys.
- **Acceptance works per line.** A `deviation()` written for one property accepts every hit on the line below it. Two of today's 7 accepted hits ride markers written for something else: `ProjectDetailPage.tsx:583/1034` accept `borderRadius: 5` under a full-width deviation, and `SearchPage.tsx:95` accepts `fontSize: 19`.
- **`phone-tiny-text` only knows phone paths it can see:** `@media (max-width ≤767px | hover: none | pointer: coarse)`, `isMobile/compact/phone… ? n :` ternaries, and files named `*Phone*`/`*Mobile*`. A raw 10 px in shared code also renders at 10 px on the phone. `font-size-literal` counts those.
- **`kit-duplicate` matches the kit's exact names.** A `TaskCheckbox` that re-implements Checkbox under another name is not caught. `createPortal` outside `components/` is flagged for judgement only: `PhoneSheets`, `TimeField`, `CaptureButton`, `VoiceCaptureSheet` and `PaperFlow` may have reasons.
- **`hover-only-reveal` (CSS)** pairs an `opacity:0` rule with a `:hover … { opacity:1 }` rule in the same file. It accepts the pair when a `(hover:none)`/`(pointer:coarse)`/`max-width` rule shows the target, or when the hiding rule sits inside a `(hover:hover)`/`min-width` query.
