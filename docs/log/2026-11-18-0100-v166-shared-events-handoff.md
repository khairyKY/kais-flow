## What it is
- **Server (migration 0101).** A shared event is **two ordinary `calendar_events` rows**, one per person, each owned by its person and joined by `shared_id` (+ `shared_with`, `shared_circle`, `share_status` = my answer, `share_peer_status` = theirs, `share_edited_by`). So the grid, reminders, Google, the feed, the widget and the MCP read it with no change, and **there is no new policy and no widening**: nobody can select or write another person's row. The link columns are written only by the sharing functions (a BEFORE guard puts them back on every client write; a forged insert is a plain event; an upsert that carries empty link columns can't unlink it).
- **Write paths (all checked on the server: caller is a member, the other person is the pair's other member, the connection is current: not paused, not left).** RPCs: `shared_event_create` (my copy accepted + an invited copy for them; a retry of the same id answers the same event), `shared_event_respond` (accept, or decline = "Remove from mine"), `shared_event_delete_both`. Plain writes through the outbox (offline-able): **editing** your own copy, which an AFTER trigger copies (title, time, all-day) to the other copy and stamps `share_edited_by`; **Remove from mine** = a plain soft delete of your copy (it stays linked in Trash, the other copy reads declined; a restore puts it back). The outbox already tags every entry with the signed-in account (`uid`), and the server stamps `share_edited_by`, so the actor of every change is recorded.
- **Leave.** The circle's delete (either side, or an account delete) turns every copy into a plain event of its own person; a proposal nobody answered goes from the invited side.
- **No answer.** Stays dashed on both until it starts, then `share_events_expire()` (pg_cron `share-events-expire`, every 5 minutes) drops both copies (an all-day one when its day ends); the client already hides it.
- **Free together.** `shared_free_together(partner, from, to)` returns `{ok, zone, partner_zone, windows[{starts_at, ends_at}]}` and nothing else: each person's own 08:00-22:30, minus both calendars' busy time (a Private item counts as busy; "show as free" and unanswered invites don't; repeats are expanded in SQL by `share_expand`: DAILY, WEEKLY BYDAY, MONTHLY by day or nth weekday, YEARLY, INTERVAL, COUNT, UNTIL, exdates, on the owner's wall clock), gaps of an hour or more, from now, at most 14 days, the same at every level (Busy is all it needs). A stranger, yourself or a pause get `{ok:false, error}`.
- **The mask learns it.** `share_day_data` gains `p_viewer`: an unanswered invitation is not drawn and not busy, and a shared event the viewer is on is never drawn a second time in their lane.
- **Client.** Her day card: **Free together** (sheet: Today / Tomorrow / This week, windows by day, Propose) and **New shared event**; one **Propose / New shared event** sheet (title, date, from, to, "Send to Reem", her clock when it differs by an hour or more); shared events on the grid (desktop + phone): her initial on the block, dashed until answered, softer when she can't go; the block menu / phone sheet: "With Reem" line, **Accept / Decline**, **Remove from mine**, **Delete for both** (asks first, then an Undo), no Private, no Repeat; Settings > Google: **"Show events I share with someone in Google"**, one switch per side (default on); the Disconnect text says shared events stay as plain events.
- **Google, per side.** `integrations.data.share_events` (absent = on), `google-connect` action `share_events`. The existing google-sync mirror (write-out) now sends an accepted shared event as an **ordinary** event (its title, not private) on its own switch, whether or not "Show my plan in Google as busy" is on; an unanswered proposal never goes. No new Google path.
