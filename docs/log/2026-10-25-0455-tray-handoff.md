## (a) Why the tray opened a signed-out window

The main window comes from `tauri.conf.json` with `"useHttpsScheme": true`, so it loads at **`https://tauri.localhost`**. `tray.rs` built the flyout with `WebviewWindowBuilder::new(…)`, which uses the default scheme, so the flyout loaded at **`http://tauri.localhost`**. A different scheme is a different origin, with its own localStorage and IndexedDB. The flyout therefore had no Supabase session, and `/tray`'s `RequireAuth` sent it to `/sign-in`.

The same split also broke two other things:
- The focus mirror (BroadcastChannel) and the `kf_theme` storage event, which only work within one origin.
- The shared outbox and read cache.

Dev builds never showed the bug because `tauri dev` serves both windows from `http://localhost:5173`.

**Fix:** every tray window is now built through one helper, `tray_window()`. It calls `.use_https_scheme(https(app))`, and `https()` reads the main window's own config value, so the two windows can't drift apart again. When the app really is signed out, the popover shows a calm "Sign in in Kai's Flow" with an **Open Kai's Flow** button (which calls `tray_open`). It never shows a sign-in form.

## What was built

- **tray.html** is a separate Vite entry (`vite.config.ts` has a second input, and `features/tray/entry.tsx` is its entry point). Before this, `/tray` loaded the whole app: router, AppLayout, every page warmed on idle, and index.html's 125% interface zoom. The `/tray` route is gone.
  - `tray.html` renders the popover. `tray.html?menu` renders the menu.
  - The menu window loads React, about 4 KB of menu code, and the kf icons. It never loads Supabase.
  - The popover lazy-loads the capture reader (chrono and the quick-add rules) the first time you focus the capture line.
  - Built sizes: TrayMenu 4.0 KB, TrayFlyout 9.0 KB, entry 1.6 KB, plus the shared react-dom chunk.
- **Popover B** (`TrayFlyout.tsx`, 340 × **480**). It holds, from top to bottom:
  - The date and Day N.
  - The Now card, drawn as §4 card A. It has four states:
    - "Up next · in 12m", with a mark (the block's check for a task, a ring in the event's hue for an event), a bar and the start/end times.
    - "Ongoing · 15m left", with the bar showing time elapsed. When two run at once, the one ending soonest leads.
    - "Next · title · time" as a quiet line when the next block is more than an hour away.
    - "Nothing else today".
  - While a focus round runs, the ring card with "Focus · 18:42 left" replaces the Now card.
  - The Top 3, with the gold star (`--acc-gold`) on the goal only.
  - The capture line with the mic.
  - The focus buttons: **Start focus · 25:00** as a terra pill, or **Pause** and **Stop** as outlined pills while a round runs.
  - The footer: **Open Kai's Flow ↗** and Settings.

  Other behaviour:
  - It closes on blur (tray.rs) and on Esc.
  - It reads the app's own IndexedDB cache. It restores it but **never writes it back**, so the main window's fuller copy isn't thinned down to what the popover reads.
  - It refetches stale queries each time it's shown.
  - Writes go through the outbox.
- **Menu B** (`TrayMenu.tsx`, `menuRows.ts`):
  - Header: the K, "Kai's Flow", and a status line: "Next · المغرب · 6:15 PM", "Now · … · until …", "Focus · 18:42 left" in sage, or "Nothing else today".
  - Rows: Open Kai's Flow, Quick capture…, Start focus 25:00 (or **Stop focus 18:42** in terra while a round runs), Pause notifications ▸ (or **Resume notifications until 7:03 PM** while paused), Settings, Quit.
  - Signed out it shows only **Open** and **Quit**.
  - Pause ▸ offers 30 minutes, 1 hour and Until tomorrow (the app's one Tomorrow: 09:00 on the user's clock).
  - Keyboard: ↑ ↓ Home End move, Enter or Space picks, → opens Pause, ← or Esc goes back, Esc closes.
  - It reaches the main window's state through tray.rs: `TrayBridge`'s `MenuForTray` sends `tray_menu`, the page reads it with `tray_menu_state` and gets live pushes through `window.__kfMenu`. The live focus time comes from the focus mirror. A picked row goes to `tray_menu_pick`, then `menu_event`, then the existing `__kfTray`. New ids: `pause:30`, `pause:60`, `pause:tomorrow`, `resume`.
- **tray.rs:**
  - Right-click opens our menu window at the pointer. tray-icon's own right-click menu is switched off with `set_show_menu_on_right_click(false)`. If that call fails, Windows' menu shows by itself, as before.
  - **Fallback:** the native 12d menu is still attached. It is popped with tray-icon's `show_menu()` in three cases:
    - the menu window can't be created;
    - the page hasn't drawn within 1.5 s of the first right-click;
    - the window exists but never drew (later right-clicks then go straight to native).

    So Open and Quit are always reachable.
  - Both windows are created on the first click and kept warm, hidden. Nothing new runs at startup, so `--minimized` is unchanged.
  - `anchor()` is a pure placement function:
    - The popover is centred over the K. The menu opens at the pointer and flips left near the screen edge.
    - Both open above a bottom taskbar and below a top one, and stay inside the work area.
    - The size is converted to physical pixels using the scale of the monitor under the click (so it works at 100/125/150%), and the window is placed twice in case Windows' DPI change shifts it.
    - It has 7 `cargo test` cases.
  - `tray_hide` now hides whichever window asked.
- **outbox.ts:** each queue read-modify-write now also holds a Web Lock (`navigator.locks`, named `kf-outbox`). The tray popover and the main window share one IndexedDB key, and two tabs already did. Without the lock, one window's write could land between the other's read and write and drop an entry.
- **focusMirror.ts:** the light half of `focusChannel`, so neither tray window loads the focus store.
