## Problems found along the way (not fixed, outside scope)
1. **The Tasks tab row sits under the Organize rail at a 1280px window with the default 125% zoom.** `elementFromPoint` at the sort control returns the rail's card, so Sort and ↻ Repeating can't be clicked at that size. This was true before and after J-12 (`{before,after}-j12-desktop-closed.png`). On phone the row runs off the screen and only scrolls sideways. I tried to file a follow-up task for this, but the tool timed out.
2. **`TZ=UTC npx vitest run` has 2 failures at the base commit** (`d14962f`), in `features/tasks/grouping.test.ts`, the "23:00 today / yesterday" cases. The B2 change moved the grouping to Cairo days, but those tests still build dates in device-local time. `TZ=Africa/Cairo` is green. My changes add no failures: 204 tests at the base, 211 now.
3. **The Review "swept HH:MM" time uses the device's clock** (`toLocaleTimeString` without a timezone), so it shows 05:13 in a UTC browser instead of 08:13 Cairo. This is the B2 family.
4. **"Close the week" probably never saves.** I found this by reading the code, not by running it. `WeeklyReviewPage.tsx` logs `review.week_closed` with `entity_id = weekStart.toISOString()`, but `activity_log.entity_id` is a `uuid` column, so Postgres should reject that write and it would dead-letter. This is the J-16 family.
5. **`Select` places its popover wrong on phone.** The code compares `window.innerWidth` (screen pixels) with layout pixels, so on phone the popover runs past the right edge (see `after-j12-phone-clicked.png`). Its option rows are about 39px tall on screen, under the 44px target. This affects every Select, not just sort.
