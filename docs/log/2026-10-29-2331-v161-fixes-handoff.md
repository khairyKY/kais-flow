## 1. "The Now/Day pill only animates going from Now to Day, not from Day to Now"

On v1.6.0 the pill sat on Today. Since today-v2 it lives in Settings → Appearance → "Phone home shows".

**The Settings control.** I measured it first. The Segmented thumb (motion-chrome O8) already slides both ways in Settings: in-page samples at about 25 ms steps show 34→196 px and 196→34 px, each with 4–5 positions in between. Nothing to fix there. It counts as chrome, so it also slides with Effects off, the same as the toggles and the motion-chrome policy; reduced motion stops it through the global rule.

**Today's views.** Nothing animated the view change, in either direction. That's fixed:
- **`ViewSwap`** (`PhoneHome.tsx`): the old view fades out over the new one fading in.
  - Each view shifts by `--sp-3` the way the thumb went: Day comes in from the right and Now from the left.
  - It uses `--dur-normal` and `--ease-standard`, with keyframes `tpSwapIn` and `tpSwapOut` in `today.css`.
  - It's the same animation in both directions.
- **When it plays:**
  - when the view changes under a Today that's drawn. `writePhoneView` now fires `kf-phone-view-change` and `usePhoneView` follows it (and `storage`);
  - when Today comes back drawing a different view than it last drew. This is the usual case, since the switch is in Settings.
- **How it's built:**
  - The outgoing copy is `inert` and `aria-hidden`.
  - `.tp-swap` is `display: contents` except while both views are present (then a 1×1 grid), so the layout is untouched.
  - The change is worked out while rendering, not in an effect, so the new view's first frame is already the first frame of the fade.
  - The outgoing copy is dropped on `animationend`. No timers.
- **Effects off or reduced motion:** the new view appears at once, and the outgoing one is never drawn.

## 2. "The Samsung lock screen widgets are not working"

### Research (sources at the end)
- **Promotion rules (Android's Live Update page).** A notification is promoted only if:
  - it's ongoing;
  - it has a content title;
  - it uses standard, BigText, Call, Progress or Metric style, with no custom content view;
  - it isn't a group summary and isn't colorized;
  - its channel isn't `IMPORTANCE_MIN`;
  - the app declares `POST_PROMOTED_NOTIFICATIONS` (a normal permission, granted at install);
  - it requests promotion with `EXTRA_REQUEST_PROMOTED_ONGOING` / `setRequestPromotedOngoing`.
- **The user can still refuse.** `NotificationManager.canPostPromotedNotifications()` (API 36) returns false when the user has turned Live Updates off for the app. The screen for that is `Settings.ACTION_APP_NOTIFICATION_PROMOTION_SETTINGS` (`android.settings.APP_NOTIFICATION_PROMOTION_SETTINGS`, with `EXTRA_APP_PACKAGE`). It may not exist on a given phone, so the app's notification page is the fallback. The `ACTION_MANAGE_APP_PROMOTED_NOTIFICATIONS` named on the Live Update page doesn't exist in `Settings`.
- **API levels.** `FLAG_PROMOTED_ONGOING` (0x00040000), `hasPromotableCharacteristics()`, `canPostPromotedNotifications()` and `setShortCriticalText` are API 36. The platform's `setRequestPromotedOngoing` and `EXTRA_REQUEST_PROMOTED_ONGOING` are 36.1 (16 QPR1), and the promoted UI (status chip, lock screen) shipped with QPR1.
  - Our request is fine on 36.0: androidx core 1.17's `NotificationCompat.Builder.setRequestPromotedOngoing` puts the `"android.requestPromotedOngoing"` extra in directly on every version (checked in the androidx source).
- **Samsung One UI 8 (Android 16):**
  - Samsung feeds Android 16 Live Updates into the Now Bar as "Live notifications".
  - In the betas, third-party apps were behind **Developer options › Live notifications for all apps**. OneSignal's docs say some One UI builds still need it.
  - Each app also has a toggle under **Settings › Lock screen and AOD › Now bar › Live notifications › View more**.
  - One UI 8.5 adds more Now Bar types.
- **Samsung lock screen notifications:**
  - One UI 7 defaults lock-screen notifications to **icons only**. Cards are opt-in: Settings › Notifications › Lock screen notifications.
  - Android has a "Show conversations, default, and silent" / "hide silent" lock-screen choice (`lock_screen_show_silent_notifications`).
  - Samsung users report that apps set to silent don't show on the lock screen. Our v1.6.0 "Lock screen" channel was `IMPORTANCE_LOW`, which Android ranks as silent.
- **LockStar:**
  - Since 2023, Good Lock's LockStar adds any app's ordinary home-screen widget, as KWGT setups do. So `widgetCategory keyguard` isn't required, though it doesn't hurt.
  - It lists widgets from the app's normal providers.
  - Since One UI 7 it sits inside the stock lock-screen editor: long-press the lock screen, then LockStar. Widgets must sit near the clock, and large ones fit badly.
- **Scheduler after an update:** it already restarts without a reboot or toggle.
  - `LockScreen.Receiver` listens for `MY_PACKAGE_REPLACED` and `BOOT_COMPLETED` (manifest receivers; system broadcasts reach `exported=false`).
  - `LockBridge.load()` refreshes on every app start.
  - `KfWidget.updateAll` refreshes on every snapshot push.
  - Nothing to fix there.

### Fixed in code
- **The Lock screen channel is no longer "silent".** It is now `lock_screen` at `IMPORTANCE_DEFAULT`:
  - no sound, no vibration, no lights, no badge (each post is VISIBILITY_PUBLIC, as before);
  - every post is `setSilent(true)` plus `setOnlyAlertOnce`, so it never alerts. setSilent sets group-alert = summary with no summary posted.
  - The Now Bar and the strip each get their own group (`kf.lock.nowbar` and `kf.lock.strip`), so they don't stack.
  - An app can't raise a channel it made, so this is a new id, and v1.6.0's `lockscreen` channel is deleted on the first refresh.
  - It's still above MIN, so promotion is unaffected.
- **Smoke:** it now checks `lock_screen` at `mImportance=3` with `mSound=null`. It also checks the old channel is absent, and the dumpsys window is widened to 600 chars, so the importance is actually in view.

### Lock screen status row
Settings → Notifications → This phone → **Lock screen status** (This device; only when the shell reports the new facts, so not on v1.6.0's shell). It has one line per option, plus **Open settings** where there's a screen that fixes it. Each option shows the first thing in its way:

| Option | Possible lines, in the order they're checked |
|---|---|
| Top 3 widget | Active · Not added in LockStar yet |
| Now Bar | Android 16 needed (this phone: N) · Off · Notifications are turned off for Kai's Flow · The "Lock screen" notifications are turned off · This phone shows no notifications on the lock screen · Live notifications are turned off for Kai's Flow · Nothing to show until 2h before your next block (from 1:30 PM / none left today) · Showing in the notifications but not as a Live notification (+ the Galaxy developer option) · Active · In the Now Bar now |
| Day strip | Off · Notifications off · channel off · no lock screen notifications · Lock screen hides silent notifications · Nothing to show… · Active, with the hint "Only an icon there? Set Lock screen notifications to Cards" |

The "hides silent" line only shows when someone has lowered the channel and the phone says it hides silent ones (`lockSilent === false`), since the channel is no longer silent by default.

**How it's wired:**
- **Native `LockBridge.state()`** reports more facts than before:
  - `release`, `notifications`, the channel's importance;
  - `promote` (`canPostPromotedNotifications`, 16+);
  - `lock` and `lockSilent` (`Settings.Secure` `lock_screen_show_notifications` / `lock_screen_show_silent_notifications`; null when the phone won't say or blocks the read);
  - `widget` (`LockWidget.placed`), `showing` and `showFrom` (new `LockPlan.showFrom`);
  - `nowBarPosted`, `stripPosted`, and `promoted` (the posted Now Bar has `FLAG_PROMOTED_ONGOING`).
- **Native `LockBridge.open(which)`** opens the screen for each fix, falling back to the app's notification page and then app info:
  - `promotion` → APP_NOTIFICATION_PROMOTION_SETTINGS;
  - `notifications` → APP_NOTIFICATION_SETTINGS;
  - `channel` → CHANNEL_NOTIFICATION_SETTINGS for `lock_screen`;
  - `lockscreen` → `android.settings.NOTIFICATION_SETTINGS`, where Samsung keeps "Lock screen notifications".
- **The words** are in `app/src/features/lockscreen/status.ts` (pure, with `status.test.ts`). The row re-reads when the app becomes visible again, for example on the way back from a system screen.
- **LockStar steps:** step 2 now mentions One UI 7+ (long-press the lock screen, then LockStar).

### The most likely cause of Kai's failure
Most likely more than one at once:
1. **Now Bar:**
   - If his phone is still on One UI 7 (Android 15), the Now Bar row was hidden and nothing could show.
   - If it's on One UI 8, Samsung likely kept third-party Live notifications off: either the per-app Now bar › Live notifications toggle, or the "Live notifications for all apps" developer option.
2. **Day strip:**
   - It is off by default.
   - When on, it went to a LOW (silent) channel, which a lock screen hiding silent notifications drops.
   - One UI 7+ also shows lock-screen notifications as icons only by default.
3. **Top 3 widget:** it only appears after Good Lock › LockStar is installed and the widget is placed by hand.

The status row now tells which one, line by line.
