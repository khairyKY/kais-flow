## What it does

**The package.** `.github/workflows/desktop.yml` gets a new job, `msix` ("Microsoft Store package"), which `needs: windows`.
- The windows job also uploads the app itself, `app/src-tauri/target/release/kais-flow.exe`, as the artifact `kais-flow-app-exe` (kept 1 day). It's the same build as the `.exe` installer.
- The msix job lays out that exe, the four logos `tauri icon` already made (`StoreLogo`, `Square44x44Logo`, `Square71x71Logo`, `Square150x150Logo`) and the filled `app/src-tauri/msix/AppxManifest.xml`.
- It runs `makeappx pack` with the newest Windows SDK on the runner. Pack validates the manifest against the schema; a negative test locally confirmed a bad attribute fails it. Then `makeappx unpack` proves the file is a whole package.
- Output is `kais-flow-<tag>.msix`, **unsigned**, uploaded as the artifact `kais-flow-msix`.
- On a release it is attached to the GitHub Release, together with a version-less `kais-flow.msix` (the download-bar pattern).
- Identity comes from the repo **variables** `STORE_IDENTITY_NAME`, `STORE_PUBLISHER` and `STORE_PUBLISHER_DISPLAY_NAME`, XML-escaped.
- Without the variables the job prints the notice *"No Microsoft Store package"*, writes a summary line and stays green.
- Version is the tag as `x.y.z.0`. A run without a tag uses `tauri.conf.json`'s `x.y.z.0`.
- `release.yml` needs no new wiring: its `desktop` job calls desktop.yml, and the called workflow reads the repo's vars itself. Only its comments changed.

**The manifest** (`app/src-tauri/msix/AppxManifest.xml`)
- `Windows.FullTrustApplication` and `rescap:runFullTrust`, x64.
- `TargetDeviceFamily Windows.Desktop`, MinVersion 10.0.19041, MaxVersionTested 10.0.26100.
- DisplayName `Kai's Flow`, with a straight apostrophe. It must equal the name reserved in Partner Center.
- A `windows.startupTask` (`KaisFlowStartup`, `Enabled="false"`, `uap10:Parameters="--minimized"`), so the Store install's **Start with Windows** opens quietly to the tray, like the .exe's Run entry.

**The app knows it's the Store install** (`app/src-tauri/src/tray.rs`)
- `store_app_id()` calls `GetCurrentApplicationUserModelId`. It returns `Some` only with a package identity.
- **Updates:** a new command, `store_install`, feeds `lib/appUpdate.ts` `storeInstall()`. `checkForUpdate('windows')` then returns `{ kind: 'store' }` without asking GitHub: no download, no "vX is out" toast, no Windows toast.
  - Settings → App says **"Updates come from the Microsoft Store"**.
  - Settings → App also hides download-bar's new "Download the apps" row there, because a Store app mustn't hand out its own .exe.
  - "Updated to vX · What's new" after a Store update still works.
- **Start with Windows:** `autostart_get` / `autostart_set` use the WinRT `StartupTask` in the Store install. The plugin's HKCU Run key would land in the package's private registry, which Windows never reads at sign-in.
  - Both commands are now `async`, so the WinRT waits stay off the main thread.
  - The .exe install still uses the plugin.
- **Toasts:** they use the package's own app id in the Store install.
- **Dependency:** `windows = 0.62` with `ApplicationModel` and `Win32_Storage_Packaging_Appx`. It's the same crate and version `tauri-winrt-notification` already pulls in, so Cargo.lock gains one line.
