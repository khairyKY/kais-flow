## F2 · weekly review reminder

- **Migration 0095** `review_reminder_on boolean not null default true` plus a new pg_cron job `weekly-review-reminder` (every 15 min, `notify` kind `weekly_review`). The existing ritual jobs are per kind, so a tick of their own was needed. DATA_MODEL has the 0095 note.
- **`supabase/functions/notify/review.ts`** (pure, shared with the app like `ritual.ts`): `weeklyReviewDue(s, now, zone)` (review day, else the weekend's first day; the loop day with the 04:00 rollover; `review_time`, 18:00 when null; the same 15-minute tick window as `ritualDue`), `reviewWeekOn` / `reviewWeekKey`, `reviewClosed` (latest `review.week_closed` / `review.week_reopened` for that week wins; a row names its week or falls back to its loop day's week).
- **notify**: new kind `weekly_review` in `index.ts` (user filter, the 9-day closed check, a `notify.weekly_review` history row). `copy.ts` has `reviewNotice(weekKey)`, tag `weekly-review-<week start date>`, and the `TOGGLE` entry `review_reminder_on`. Quiet hours send it silent; pause and the switch send nothing (`deliver`).
- **App**: `localPlan` fires the same notice with the same tag (Windows / Mac sweep, Android a week ahead). `TrayBridge` reads the closed rows through a new `useReviewClosedRows` plus any `review_week` cache the Weekly review has folded a close into, and waits for them before the first sweep. `KIND_LOOK.weekly_review` (Rituals channel, clipboard glyph, the evening nudge's colours), `soundOf` maps it to the evening nudge's sound. Settings: a Weekly review switch in Notifications → Kinds (bound to `review_reminder_on`, not `<kind>_on`), and the Time → Weekly review help line ends with "You'll get a reminder at 6:00 PM" (12/24-hour aware, hidden when the switch is off). The Activity history row opens `/weekly-review`. MCP `update_settings` accepts `review_reminder_on`.
- **Deviations from the spec:** the route is `/weekly-review` (there is no `/review`); the button is `{action: 'open', title: 'Start review'}`, because the existing `review` action id already means "paper capture ready" (Inbox + results) and `open` already navigates to the notice's url on every channel (web SW, Windows / Mac toast, Android). No new `NoticeAction` id. With no `review_day` the reminder follows the weekend's first day (default weekend: Saturday 18:00), so a user who never touched the setting gets it; `plan.test.ts` therefore sets `review_reminder_on: false` in its base prefs. Skipped a new `supabase/tests/*.sh` suite: the logic is pure and unit-tested in four zones, and Rehearsal applies the migration and runs the existing notify suites.

## F3 · Mac notifications with buttons (`app/src-tauri/src/tray.rs`)

- A notice with actions now goes out with `MainButton::SingleAction` (one) or `DropdownActions("Actions", …)` (two or more, at most four, the app's order) plus a "Dismiss" close button, sent on its own thread. Press → the action id found from the label (`action_for_label`, pure, unit-tested with `button_labels`) → `__kfNotifyAction("<id>",{payload})`, exactly the Windows contract. Click on the notice → `show_main` + `__kfNotifyAction("open",{payload})`, so the app opens on the notice's url. Dismiss / nothing → nothing. Windows block untouched.
- **Ceiling:** 6 waiting notices (`Slot`, an atomic counter); the 7th and later go out as plain banners, as before. `mac-notification-sys` 0.6.15 has **no timeout** on its response wait (checked in the crate source), so the 12-hour give-up in the spec is not possible; a thread frees when its notice is pressed, dismissed or cleared. The `ponytail:` comment names that and the upgrade (a UNUserNotificationCenter delegate through objc2).
- Sound and icon unchanged (the app plays the pack sound; the notice goes out silent when it did).
- Settings test on Mac: the test notice carries one Open button, and the result line says "Buttons show on hover; set Kai's Flow to Alerts in System Settings › Notifications to keep them on screen." The notice style can't be read from the app, so it is shown unconditionally on Mac.

**Manual checklist for Kai's Mac tester** (install the Desktop apps run's Mac build):
1. Settings → Notifications → "Send a test notification": a notice with an Open button appears (hover it if it is a banner); pressing Open brings the app forward.
2. Add a task with a reminder 2 minutes ahead: the notice shows Done / In 10 min / In 1 hour / Tomorrow in a dropdown; pick Done and the task ticks in the app.
3. Repeat with Tomorrow and In 10 min (the task moves / reminds again).
4. Click the body of a task reminder: the app opens on that task.
5. Let a notice sit in Notification Center, then fire 7 reminders at once: all appear; only the first 6 have buttons. Set Kai's Flow to Alerts in System Settings → Notifications to keep buttons on screen.

## F4 · break-end notice

- `copy.ts` `breakDoneNotice(nextRound, totalRounds, task, autoStarted, p)`: kind `break_done`, tag `focus-break`, switch `focus_done_on`. Auto-started: "Back to it" / "Round n of N" and no buttons; otherwise "Break's over" / "Ready for round n?" with Start (`focus_start`) / Stop (`focus_stop`). The task name only with lock-screen names on. N is the block's rounds, else rounds before a long break.
- `notifications/breakEnd.ts` `breakEnded(prev, s)` (a running break at its last second that became a round; a hand skip leaves time on the clock). `TrayBridge.watchFocusDone`: notice when nobody is looking, only the pack's `break_end` sound when the app is in front (the Focus page never gets a notice); Android pre-schedules it at the break's end like the round's. `soundOf`: `break_done` → `break_end`. `runNotificationAction` handles `focus_start` / `focus_stop` (all channels route through it).
- `break_done` has no `KIND_LOOK` entry or Kinds row (it shares the Focus switch) and no history row.
