## What I built
- **Create, desktop.** A drag across several days in the all-day band (and across columns in the time grid) opens QuickCreate with the full range. The popover and the full page now have an **Ends** date (popover: a chip "+ Ends another day", opened by itself when you dragged across days) and an **All day** switch; the range reads under it ("Wed 21 – Fri 23" / "Mon 22:00 – Tue 02:00"). Changing the start date keeps the length in days; an end before the start lands on the start; a timed end not after its start becomes start + 30 min. `slotFields` now returns `endDate` (all-day: FullCalendar's exclusive end minus a day).
- **Create, phone.** Event kind in the create sheet has an **Ends · date · time** chip (date picker with Set time; date only when all-day) and an **All day** chip. It defaults to the start day; the duration chips reset it to the same day.
- **Edit, desktop popover and phone sheet** (same `blockMenuSpec`): an event's **Date row is now Starts**, plus an **Ends** row (date, and time via the picker's Set time) and an **All day** switch row. Starts moves the event and keeps its length; Ends clamps. A task's block keeps its single Date row. The one-day **Time** row steps aside for a timed event that ends on another date (Starts / Ends carry the times); LengthChips / TypedTime are hidden for those. Everything goes through `setEventRange` (`scoped.ts`) → `moveBlock`: a repeat asks This / Following / All, one Undo. Google events that are ours to change get Starts / Ends too (the existing `google-sync` `edit` writes it; read-only ones just show Ends when they run past a day). All-day on keeps the dates; off gives 09:00–10:00 on the first day (QuickCreate and the phone chip keep the times they still hold).
- **See.** Band pieces: the first reads "Trip »" (timed: "Conference · from 9:00 AM »"), a continuation counts itself ("« 2/4 »"), the last "« 3/3 · until 5:00 PM" (was "ends"). Phone chip: "« Trip · day 3 of 4 »", and for a timed span in Day view on a middle day "all day (Tue 9:00 AM – Thu 5:00 PM)". **Today** has no all-day line at all, so a new plain `SpansToday` list ("Trip · day 3 of 4") sits next to the birthday cards (desktop and phone); a one-day all-day event is still left off. Now / Up next / the ribbon take a timed span of a day or more only on the day it starts or ends (`runsToday` in `today/upNext.ts`); an ordinary event over midnight is unchanged. The week strip in the widget snapshot counts a multi-day event on every day it covers.
- **Drag / resize, desktop.** A band piece drags the **whole span** by days (times kept, DST-safe `shiftDays`); dropped on the time grid it goes back. FullCalendar can't resize the pieces (each is one day), so the first and last piece carry a small **grip** (`spanGrip.ts`): drag left/right in whole columns, a tip names the range, release commits (scope question + Undo). Read-only (ICS / not-ours Google) spans have neither.
- **MCP.** No code change needed: `add_event` / `edit_event` already take an `end` on a later date (timed up to 31 days, all-day too), `spanText` reads "2028-01-19 – 2028-01-21" / "…22:00–2028-01-19 17:00", and `calendar` lists a span once. New cases in `mcp-week.sh` pin that (add a timed 3-date span, listed once, end moved to a later date, an end before the start refused).

## Choices the spec left open
- Continuation pieces show `n/N` and keep the title only on the first visible piece (the 3e design rule), rather than the title on every piece.
- Starts = move keeping the length (the old Date row's behaviour, and Google's). Extending is the Ends row.
- "All day" is a row/switch on events; it isn't offered on Google events (google-sync would need a separate all-day flip).
- Widgets: only the week-strip counts follow multi-day. The timed-blocks list is unchanged (a middle day of a timed span would draw a block starting before today); Android and the desktop widgets read the same snapshot, so they match. The desktop-widgets feed branch isn't in this base: check its day filter when it lands.
