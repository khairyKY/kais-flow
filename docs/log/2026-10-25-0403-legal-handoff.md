## 2 · Built

**Policies reachable everywhere**
- Settings → **Privacy & terms** (side nav item too): Privacy Policy · Read, Terms of Use · Read (each "Updated 25 Oct 2026 · you agreed …"), and one line on what's kept where. Desktop + phone.
- Sign-up and sign-in: small footer "Privacy Policy · Terms of Use". Site footer already linked both.
- Every link goes through `openExternal` (`features/legal/LegalLinks.tsx`): new tab on the web, system browser in Windows / Android.

**Acceptance at account creation**
- A required box "I agree to the Terms of Use and the Privacy Policy" (both linked; a tap on the line ticks, a tap on a link opens it). Create account stays disabled until ticked; Enter doesn't submit either.
- Recorded server-side: the versions go as sign-up metadata; **0083**'s trigger on `auth.users` writes `consents` rows at account creation (works with Confirm email on, no session needed; never blocks a sign-up).
- **Choice: a `consents` table**, not app_settings — it keeps a history (which version, when), one row per document version. RLS select / insert / update own (update = outbox upsert retry), `set_updated_at`, no delete grant.
- Versions in one place: `supabase/functions/_shared/legal.ts` (`TERMS_VERSION = PRIVACY_VERSION = '2026-10-25'`, `LEGAL_SUMMARY`). The app and `notify` import it; the site reads both dates out of it at build time. A test fails if `app/public/privacy.html` wasn't regenerated.

**"We've updated our terms" notice**
- Shown when the newest agreement is older than the current version, or missing (every account before 0083 — Kai's included, once). Calm card over the app: what changed (3 lines), both links, **I agree** (writes `consents` through the outbox), ways out: Export my data · Delete my account · Sign out. Esc / tap outside don't close it. Unknown (offline, nothing cached) → no card.
- Outside the app: `notify` kind `terms`, cron `terms-notice-sweep` hourly (0083) — once per person per version: a `notify.terms` Activity row (the in-app notice; written first, so it's also the idempotency mark) + "Our terms changed · Tap to review" to their push devices. Pause → next run. Activity's row opens Settings.
- **Email: skipped** — no $0 email path exists (details in LEGAL.md).

**Policy text** (`site/src/pages/info.mjs`, Kai's voice, same structure): §1 notes the agreed version; §3 → "Google Calendar and GitHub"; §4 names Supabase emails, push services, GitHub updates; §5 rewritten (Export + Delete account in Settings, backups gone after 14 releases); §6 + Terms "Changes" say the app asks you to agree; Terms "Using it" (creating an account = agreeing) and "Ending" (delete it yourself). Rebuilt: `node build.mjs` (31 pages), `check-links` (1290 links, all resolve), `app-privacy.mjs`.

**Delete account** (was missing): Settings → Your data → Delete account…, and from the notice. Type DELETE (any case), "Export everything first (.json)" offered. Google disconnected first, then `delete-account` (service role: the user's Storage photos in `captures` + `journal`, then `auth.admin.deleteUser`; every table cascades), then signed out with a toast. Web / Windows / Android: plain fetches. Added to `config.toml` (`verify_jwt = true`) and `release.yml` FUNCTIONS.

**Queue item 6 — password eye**: kf `eye` / `eye-off` glyphs (24 grid, stroke 1.6, round caps), the button shows only the eye, its name toggles "Show password" / "Hide password". Edge / WebView2's own reveal eye (`::-ms-reveal`) hidden — that was the second eye Kai saw on Windows. Applies to every password field (sign-in, sign-up, reset: all `PasswordField`).

Also: `consents` added to the JSON export.
