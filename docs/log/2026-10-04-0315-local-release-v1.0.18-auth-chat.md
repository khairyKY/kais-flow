# v1.0.18 — sign-up emails lead back to the app; chat answers; GitHub leads to the issues

Rollback point: `b67767e` (v1.0.17 on master).

**What's in it:**
- **Auth links** (the release pipeline's auth step):
  - every release sets the hosted project's **Site URL** to the live app, and its **redirect allow-list** to the app + `https://localhost` (Android) + `tauri.localhost` / `tauri://localhost` (Windows);
  - it also sends the **branded email templates**. If Supabase refuses templates without custom SMTP, it warns and still sets the links.
  - Before this, the confirmation link went to Supabase's factory `http://localhost:3000`, because the app's emailRedirectTo is ignored unless it's allow-listed.
  - Gmail SMTP, the email rate limit and the Confirm switch still wait for `SMTP_USER` / `SMTP_PASS`.
- **Chat:**
  - the prompt now carries a live snapshot (today's / overdue / tomorrow's tasks, today's and tomorrow's calendar, the inbox count) and a short guide to the app;
  - it may reason over the user's data but never invent it;
  - it replies in the user's language.
  - It used to answer "That's not in your data" to almost everything.
- **Settings → GitHub:** says what Connect does, and a connected card leads with "See issues in your Inbox →".

**Evidence:**
- `tsc -b` 0, lint 0 errors, chat prompt tests in 3 TZ (CI runs ×4).
- cleanup harness 52/52 on the change.
- The auth payload dry-run, with and without SMTP secrets: site_url + allow-list always; SMTP + autoconfirm only with the secrets.
- The live PATCH result shows in the Release run's summary.
