# Audit: brand-new user (Phase B) and whole-product state (Phase A)

**Code audited:** `origin/claude/release-1` at `cdc55c8` (master + T-1/T-2/T-3). Dev server on :5210, plus a production build (`npm run build` + `vite preview` on :5211, service worker active) for the offline pass. Local Supabase stack (shared, not reset). Chromium 1194 via Playwright.
**Browser time zone:** Part 1 ran in the container default (**UTC**), so a public user outside Cairo is simulated. Part 2 ran with `timezoneId: 'Africa/Cairo'`, which is Kai's own setup.
**Accounts:** `audit-new@example.com` (created through the app's own sign-up form), `audit-full@example.com` (seeded over REST with its own JWT, so RLS applied: 30 tasks, 2 domains, 2 areas, 3 projects with "Kitchen renovation" slipping at 25 days, 3 routines + 12 completions, 5 events with 3 overlapping, 2 journal entries, 2 people, 5 inbox items).
**Screenshots:** `docs/log/assets/audit/` (28 files). Known-item refs: J-n = judging registers, S/B/D/H-n = `docs/SECURITY-AUDIT-2026-08-01.md`, punch-n = `design-integration/V1-PUNCHLIST.md`, T-n = conductor tickets.

**Status of this entry:** complete. Part 1 was written at 05:33 UTC and pushed first; Part 2, the gap table, the top 10 and the "could not check" list were added at about 06:10 UTC.

## TL;DR

- **Three data-loss bugs, all NEW:**
  1. Every new **person, interaction, time entry and library item** is rejected by the server, because the client sends `user_id: ""`. The UI shows the item as saved anyway.
  2. **Typing in the Journal offline** saves one entry per keystroke: "Written while offline." became 22 one-letter entries.
  3. **Signing out while offline** deletes the queued writes, and the user stays signed in.
- **Calendar (Cairo):** the day labels are one day behind in any time zone ahead of UTC, Cairo included. Today's events sit under "FRI 25", and the "SAT · TODAY" label sits over an empty column.
- **Phone:** Tasks and Projects can't be reached from the navigation at all.
- **Sign-up:** a new account goes straight to Today and skips onboarding.
- **Error page:** a bad URL (or any render crash) shows React Router's "Hey developer 👋" screen.
- **What works:** RLS isolation between the two accounts, CSV import with 0 duplicates on re-run, inbox file/dismiss with Undo, trash and restore, recurring completion (no duplicate), night theme, and offline complete/quick-add/capture syncing after reconnect.

### Offline pass (production build, `context.setOffline(true)`)

1. Offline → topbar "OFFLINE ◌".
2. Complete "Send invoice to Horizon Ltd" → "2 SAVED HERE".
3. ⌘K "Offline test task tomorrow 4pm" → "4 SAVED HERE".
4. ⌘Enter AI capture → toast "Offline — captured, will process when back online" → "6 SAVED HERE".
5. Navigate to `/journal`, type "Written while offline." → "50 SAVED HERE".
6. Hard navigation to `/tasks` offline → boots from the SW + cache.
7. Back online → "SYNCED" within 8s; outbox empty.

**DB after reconnect:**
- Task done ✓.
- "Offline test task" due 2026-09-27 13:00 UTC (= 16:00 Cairo) ✓.
- Inbox item `pending` with `{"needs_parse": true}`. It stays that way, since parse-capture 503s locally. The user gets no signal it was never parsed.
- **Journal: 22 separate `journal_entries` rows for 2026-09-26, bodies "W", "r", "i", "t", "t", "e", "n", " ", "w", … "."** plus 22 `journal.created` activity rows (`p2-journal-offline-one-entry-per-keystroke.png`).
- Cause: `JournalPage.tsx:167-172` `startFirstEntry` creates a new row on the first keystroke of an empty day. `writeRow` skips the optimistic insert when the `journal_entries` query has no cached list (`outbox.ts:171`: `if (!old) return undefined`), so the day still looks empty and every keystroke calls `startFirstEntry` again.
- Would-be trigger online: typing before the journal query has loaded, or after it errored. Not reproduced online.

**Offline sign-out (S7 path):** offline, ⌘K "Signout-loss probe task" → "2 SAVED HERE" → Sign out.
- `signOut()` flushes (fails offline), **deletes the outbox and dead letters** (`AuthProvider.tsx:61-64`), then `supabase.auth.signOut()` throws `TypeError: Failed to fetch`.
- The user **stays on `/today`, still signed in, with no message**.
- Back online and signed in again: the probe task is **not in the DB**. Lost silently.

**Dev-server note (not a product bug by itself):** on `npm run dev` there is no service worker, so the first ⌘K offline failed to fetch the lazy `CommandBar` chunk. The whole app then fell to React Router's developer error screen. In the production build the SW precaches the chunks (206 entries) and this did not happen. It shows that any chunk-load failure, e.g. a stale deploy, lands on the "Hey developer" screen, because no route has an `errorElement`.
