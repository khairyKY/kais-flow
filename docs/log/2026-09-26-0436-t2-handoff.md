# T-2 handoff: schedule shortcuts on Cairo days

Branch `claude/t2-cairo-shortcuts`, fix commit `ba4a4d6`. Not merged, no PR opened.

## What changed

- `app/src/lib/dateShortcuts.ts`: `scheduleToday`, `scheduleTomorrow`, `scheduleThisWeek` and `scheduleNextWeek` now return **09:00 Cairo wall-clock** on the right **Cairo** calendar day. `daysUntilNextMonday` uses the Cairo weekday. Exported names and signatures are unchanged, so no call site changed.
  - The Cairo day comes from the existing `cairoDateKey` (private `cairoDayUtc`), and all day arithmetic runs on that date.
  - Cairo wall-clock is converted to a UTC instant by private `cairoDayAt`, which gets the offset from `cairoOffsetMs`. `cairoOffsetMs` reads it with `Intl.DateTimeFormat({ timeZone: 'Africa/Cairo' }).formatToParts` and makes a second pass for DST. There is no hardcoded +2/+3 and no new dependency. The device-local `atHour` is gone.
- `app/src/lib/dateShortcuts.test.ts`: rewritten. The old expectations were device-local and passed only when the machine was on Cairo time. It now has 20 tests using explicit instants and ISO values worked out by hand:
  - a normal summer day
  - a winter day, including a year rollover
  - a `now` that is a different calendar day in Cairo than in UTC (summer and winter)
  - the spring DST week (Fri 2026-04-24), including the last winter half-hour and the minute just after the jump
  - the autumn DST week (Thu 2026-10-29 24:00), including both runs of the repeated 23:30
  - the Sunday/Monday edges of `daysUntilNextMonday`, including the minutes where the UTC day is still the previous day
- `app/src/features/tasks/grouping.test.ts`: fixture only.
  - `NOW` is now `2026-07-08T15:00:00+03:00`, and `at()` builds Cairo instants.
  - The Next-week regression test pins `now` in Cairo time. It uses the Cairo weekday for its Sunday case and also runs at 01:00 and 23:30 Cairo. At 15:00 Cairo alone the device day equals the Cairo day in all four test zones, so without the extra times the test could not catch the bug.

## Deviation from the brief (fixture only)

## Open questions / unsure

1. **Editor and calendar are still device-local.** On a non-Cairo device, a shortcut-scheduled task now shows its due chip as 09:00, because `formatDue` renders in Cairo. But `TaskEditorPage` and the FullCalendar grid render it in device time. Before T-2 the mismatch ran the other way. Worth a follow-up ticket for `ScheduleMenu`/`SnoozeMenu` custom dates, `TaskEditorPage` and `parseCommand`. A small exported "Cairo date key + hour → ISO" helper from `dateShortcuts.ts` would serve all of them. I did not export one, to keep this diff surgical.
2. `settings.timezone` exists (`SettingsPage.tsx:303`), but nothing in `app/src` reads it for day math. `cairoDateKey` and the shortcuts hardcode `Africa/Cairo`, per the B2 ruling. If that setting is meant to drive the day boundary, both would need to take it.
3. I added three small private helpers (`cairoDayUtc`, `cairoOffsetMs`, `cairoDayAt`) and one formatter rather than exactly one helper. It is still dependency-free and about 30 lines.
4. `docs/log/` did not exist before; this file creates it.
