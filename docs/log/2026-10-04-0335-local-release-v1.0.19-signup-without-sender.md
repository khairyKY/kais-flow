# v1.0.19 — sign-ups work while there's no email sender

Rollback point: `a9c5104` (v1.0.18 on master).

- **The problem:** the hosted project required email confirmation, but its only sender is Supabase's built-in one. It delivers only to the project's own members, at about 2 an hour, so every new sign-up waited for an email that never came.
- **The fix:**
  - The release's auth step now sets `mailer_autoconfirm = true` (confirmation **off**) whenever there are no `SMTP_USER` / `SMTP_PASS` secrets.
  - `supabase/config.toml` `enable_confirmations` is now `true`, so the release that adds the Gmail secrets switches confirmation **on**, as Kai decided on 2026-09-27.
  - Existing unconfirmed accounts can sign in while it's off.
- **v1.0.18 working:** Kai's click on an old link landed on our own "link expired" screen (`/sign-in?expired#error_code=otp_expired`), not localhost:3000. Links are single-use and last an hour.
- **Evidence:** payload dry-run (no SMTP → autoconfirm true; with SMTP → autoconfirm false); YAML valid.
