# v1.6.6 partner sharing P2, flow 6: the "Her day" widgets (branch claude/v166-share-widget, from claude/v166-sharing)

Kai's picks (Partner sharing P2 flows.html section 6, Sharing looks.html item 9): one size 4x2, a Rainmeter skin that asks every 5 minutes with its own key, out of date after 24 hours = greys out and hides titles. Not merged, not released. Migration **0104**.

## What was built
- **Server (0104 + function `share-widget`).** `share_widget_links`: a key held by the VIEWER that names ONE person (`owner_id`). Its own kind, not a use of the Widget link: the `widget` function (kf_w_) reads the holder's own plan and can't see this table; `share-widget` (kf_p_) can't see a Widget link; each refuses the other's token. The key can only ever reach `share_widget_read(hash)` (no app role can call it): it counts the call (60 an hour), checks the key, reads the connection **live** exactly as `shared_day` does (lower of both levels, the pause) and returns `share_day_data()`'s masked answer for the person the key names. Never a raw row, never the holder's own day. The function expands repeats and picks now / next (`supabase/functions/share-widget/feed.ts`); no ids leave. 401 / 410 / 429 / 200 `paused` / 200 `ok`.
- **Respect the connection.** Level lowered, pause, disconnect: each applies on the very next call (no cache). Stop (Settings) is for good (`revoked_at` can't go back to null); **a disconnect stops every key between the two people, both ways, for good** (before-delete trigger on `circle_members`), and connecting again does not revive one.
- **Settings > Sharing > Widgets** (`sharing/herWidgetKeys.ts`, `SharingSettings.tsx`): per connected person, "Make a key" (shown once, only its SHA-256 is sent, Copy), "Stop this key". Nothing without a connection.
- **Android W42 "Her day" 4x2, one size** (`HerDay.java`, `HerDayPlan.java`, `kfw_herday.xml`, `kfw_blk_her.xml`, `kfw_w42.xml`, receiver, strings). Her round initial in Heather, name, level, "Top 3 . 1/3" (Details); her block Now (live "left" countdown) and Next in Heather with the dashed edge; at Details her goal with the star; a Busy block says "Busy"; no editing, a tap opens the app. Existing tokens only (kfw_blk_heather*, kfw_gold, KfW styles). It needs no key: the app feeds it `shared_day` through its own session (`widgets/partnerSnapshot.ts`, snapshot key `partner`; WidgetBridge reads her day like her card on Today). States: nobody connected ("Share your day with someone" + Open Sharing), paused (name and when it ends), out of date.
- **Out of date (24 h).** Phone: the widget compares the snapshot's `partner.at` with the clock at draw time (so it works with the app closed), greys out (alpha), every title says "Busy", goal and Top 3 hidden, a stale stamp with when it was last read. The widget's alarm is set for that moment. Rainmeter: same rule off the last good answer; a stopped key / disconnect (401 / 410) wipes the day, every word in every meter, the saved key, and stops the polling.
- **Rainmeter skin "Her day"** (`desktop/rainmeter/Glass/KaisFlow/HerDay`, `@Resources/KaisFlow/herday.lua` UTF-16 like widget.lua, `HerDay.inc`, `sample-her-feed.json`). Its own key file `%APPDATA%\Rainmeter\KaisFlow-her-link.txt` (never the Widget link's), `UpdateRate=300` on a 1 s skin = 5 minutes, only accepts a `.../functions/v1/share-widget?t=kf_p_...` link. Right-click: Open Kai's Flow, Add or change her-day key, Theme (same theme file as the other skins), Rebuild glass. **Package 1.2** (`docs/log/assets/v166-share-widget/Kais-Flow-widgets-1.2.rmskin`; build-rmskin / read-rmskin updated; the five 1.1 skins are untouched).

## Decisions for Kai
1. **Heather dashed edge on the phone widget** uses a new drawable (`kfw_blk_her`, the Heather tokens with a dashed stroke). No new colour.
2. **No "Free together" footer and no status line** on the widget: those are other P2 builders' data (free together, status 0103). The header shows the level ("Details") where the design shows her status; the footer (Rainmeter) shows when it was read. Add them when those land (a field each in `partnerSnapshot.ts` and the feed).
3. The phone widget **refreshes when the app runs** (15 minutes keep-alive, on resume, Realtime pings), plus Android's own 30 minutes redraw; with the app closed it can't ask the server, so after 24 hours it greys out (the rule you picked).
4. A key's 60 calls an hour means the skin may poll every 1 minute at most; it polls every 5.
5. The widget's picker entry has no preview image (the others have a webp from the widgets-build renderer).
