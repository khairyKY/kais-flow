# What's new: one notes file, a site page, and the app tells you about updates

Branch `claude/whats-new`, cut from `origin/claude/wave-s` at 1110074 (the v1.0.21 release branch). Not merged, not deployed. No migration.

## Where the notes live

**`site/src/releases.json`** is the only place release notes are written. It's newest first, one entry per version:
`{ v, date, title?, highlights: [...], icons?: [...], art }`. `icons` is one `site/src/icons.mjs` name per highlight, drawn on /whats-new/. An unknown name now fails the build.

Everything else reads that file:

- **The site:** Field notes, the RSS feed, `LATEST` (the download cards' fallback version) and the new /whats-new/.
- **The app:** imports it at build time (`resolveJsonModule`; vite's dev server may read that one file outside app/). `vite.config` also stamps its newest `v` into `/version.json` as `version`.
- **The release workflow:** writes the tag's entry as the GitHub Release body.

v1.0.18–v1.0.20 were already there. I added **v1.0.21** (7 Oct): your own time zone, AI assistants over MCP, rename / change type, domains everywhere, search opens the thing + editable status updates, easier number fields.

**A new release:** put its entry on top of releases.json *before tagging*.

## App

- **After an update:** on the first launch of a newer version than this device last saw, a toast says "Updated to v1.0.21", with a **What's new** action.
  - It shows once per version. Memory is per user, in `localStorage` under `kf-whats-new:<uid>`.
  - On a first launch with nothing remembered, a brand-new account (signed up less than a day ago) gets no toast, because it didn't update. An older account hears once, which covers this feature's first rollout.
- **A newer version:** the quiet check runs on start and when the app comes back into view (the Windows app lives for days in the tray), **at most once a day**. Opening Settings also runs it.
  - When it finds a newer version, a toast says "v1.0.22 is out", with a **See what's new** action. Each version is toasted once.
  - The check reuses `checkForUpdate` from `lib/appUpdate.ts` unchanged. On the web, a newer deploy of the *same* version is not news.
  - A release whose installer is still building isn't toasted yet, and isn't marked as told.
- **Windows:** the same copy also goes out as a system toast through tray.rs `notify_local`. Its button runs `__kfNotifyAction('whats-new')`, which calls `tray_open` and opens the sheet.
  - There's no system toast while someone is looking at the window (the in-app toast covers that), in quiet hours, or while notifications are paused.
- **The sheet:** a BottomSheet on a phone, a centred card on a computer.
  - It shows "What's new in vX", "Your version" or "Ready to update" with the date, the release title, and the highlights.
  - "All release notes →" opens the site's /whats-new/ outside the app (`target=_blank`, like the app's other outside links).
  - The primary button is **Got it** for the running version, or **Update** for a newer one: a reload on the web, the installer download on Android / Windows (both from `lib/appUpdate.ts`).
- **Notes for a version newer than the bundle:** read from its GitHub Release body (the `- ` lines). The native check already fetches `releases/latest` and now hands the body on; the web makes one extra call, only when version.json names a newer version.
- **Settings → App:**
  - It checks on open, and the version number shows on the web too ("v1.0.21 · build abc1234").
  - "Coming in v1.0.22" lists that version's notes beside **Update**.
  - "What's new in your version (v1.0.21)" is a folded list.
  - A same-version redeploy still shows the old "A new version is ready · Reload".
- **Release workflow:** the publish job sparse-checks-out releases.json at the released commit. It writes title + `- highlight` lines + the "Live at" line as the body, using `--notes-file`. With no entry, it falls back to `--generate-notes` with a warning.

## Deviations / risks

- **The site isn't deployed yet** (kais-flow-site.pages.dev doesn't resolve). The app's "All release notes →" points at `https://kais-flow-site.pages.dev/whats-new/` (`RELEASE_NOTES_URL` in `lib/whatsNew.ts`, the same default as `site/build.mjs`). **Kai:** deploy the site with this release (site/README), or change that one constant if it lives elsewhere. Until then the link is dead.
- **The Windows side of the system toast is only checked against a stub.** tray.rs is unchanged and already ships `notify_local`, its button → `__kfNotifyAction`, and `tray_open`. The real toast only runs in the CI-built installer.
- **Quiet hours skip the system toast; they don't delay it.** That version is still marked as told, and the in-app toast is shown. This is deliberate: never nag.
- **First rollout:** every existing user sees "Updated to vX" once on their first launch of this build (nothing was remembered before). That's intended. A fresh install on an older account also hears it once.
- **The web app rarely shows "is out":** the service worker auto-updates on navigation / visibility, so most web users go straight to "Updated to vX".
- **The release body:** the jq expression couldn't run locally (no jq on this laptop). It's simple, and its output is parsed by `highlightsFromBody`, which is tested on the same shape. GitHub's ubuntu runners have jq (the deploy job already uses it).
- **The bundle:** releases.json is ~6 KB in the main chunk (all notes, including site-only `art` / `icons`).
