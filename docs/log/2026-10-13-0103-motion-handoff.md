# Motion: the stack, the filing drag, the soft no, boundary resistance, the long-press bloom

Branch `claude/motion`, cut from `origin/claude/kai-bugs-1012` @ 1fbfbb63, then the base merged in again @ c2b12a6a (Night, calendar follow-up, rehearsal). Commits: `5bc107d1` (the feature), `afc2efec` (base merge), plus this handoff commit. Pushed, not merged, not deployed. No migration, no edge function, **no new dependency** (`@dnd-kit/core` was already installed for the Top 3, routine-step and paper-page drags).

Every motion is transform/opacity only, reads `useMotionEnabled()` / `motionOnNow()` (reduced motion **and** the animations toggle) and turns into a cut or a still state when either is off. Every drag is a mouse drag on a computer, and every one is an action the row's ⋯ menu (or the board card's menu) already has by tap and key: nothing new to learn, nothing that only a drag can do.

## How it's built (one place each)

- **`lib/motion.ts`**: `stackMove(from, to, action, back)` (pure — which way a navigation goes; tested), `captureStack` (called from the router subscription before the next page renders: saves the outgoing page's scroll by history key and, motion on, a still copy of it), `useStackTransition` (plays it on `.app-main-content` before paint; a replace or search-param settle mid-move leaves it alone, any other new page stops it), `resist()` (pure curve, tested) + `useBoundaryResistance`, `playOnce` / `softNo` (one-shots on a `data-play` attribute, so a re-render that rewrites `className` can't wipe them), `motionOnNow()`.
- **`App.tsx`**: one `router.subscribe` registered before `RouterProvider` mounts (reads `history.state.idx` for Back vs Forward).
- **`components/AppLayout.tsx`**: `<DragShell>` around the shell, the stack's CSS next to the other shell motion (3c etc.), `scrollerRef`, Esc pops a detail (after `lib/overlayStack` has had its turn), and the three sidebar drop spots (`SpotLink`, `NavRow`).
- **`components/drag.tsx` + `drag.css`** — the shared drag kit on `@dnd-kit/core`: `DragShell` (one DndContext for the shell, `pointerWithin` collisions, auto-scroll, a11y announcements), `DragRow` (a row you pick up; its slot), `DropZone` / `useDropSpot` (a place; its highlight), the ghost (its own fixed layer placed from the raw pointer in CSS px under the root zoom — dnd-kit's `DragOverlay`/`delta` are off by the 125% zoom and fold in scroll offsets). A load says what it does where it lands (`verdict` → true / false = soft no / null = not a place for it, and `drop`); a spot only says what it is, so the sidebar takes a task and a capture without knowing either.
- **`features/tasks/fileDrop.ts`**: `taskVerdict` / `inboxVerdict` / `projectVerdict` (pure, tested in `fileDrop.test.ts`) and `dropTasks` (the menu's own api helpers).
- **Feature wiring**: `tasks/TasksPage.tsx` (rows → `DragRow`, rail areas/projects → `DropZone`), `tasks/TaskRow.tsx` (star soft-no), `tasks/SwipeRow.tsx` + `TaskRow.css` (2l), `inbox/InboxPage.tsx` (cards + GitHub rows → `DragRow`), `projects/ProjectsPage.tsx` (board cards + columns).
- **`styles/tokens/motion.css`**: `--dur-stack`, `--ease-stack`, `--stack-dim` (0.39 × `--scrim` ≈ 2b's 14%; 0.33 on a phone ≈ 3a's 12%), `--shadow-stack-y/x`, `--shadow-lift`, `--dur-ghost-home`; keyframes `stackOverIn/Out(X)`, `stackUnderIn/Out(X)`, `stackDimIn/Out`, `dragFloat`, `softNo`, `dropCatch`, `pressBloom`.

## Not built, and why (judged a gimmick or out of lane)

- **Task-list drag reorder (2c's demo)** — tasks have no manual order column; every list is sorted (Smart / due / priority). A drag that the next sort undoes is decoration; a real one needs a migration + a "manual" sort mode. The reorders that *are* real (Top 3, routine steps, paper pages) already drag.
- **Journal day push/pop** — days are siblings (prev/next in place), not a drill-in; no frame draws them as a stack. Pushing a sibling would lie about where you are.
- **Domains as drop targets** — `features/domains/DomainList.tsx` is outside this lane. One-line follow-up: wrap its row in `DropZone` with `{ kind: 'place', to: { kind: 'domain', … } }`; `taskVerdict` already handles it.
- **Inbox → Someday / → a project** — the inbox api has no "file as someday"; no project list is on the Inbox page (the card's place chip + File already does it). The Someday row simply isn't a target for a capture.
- **Sheet-edge rubber band** — 2k's frame draws a list, not a sheet; `BottomSheet` isn't in this lane.
- **2c's velocity tilt and 110ms trail; 4d's sage wash on the edge zone** — the calendar's ghost doesn't do them either; the float + lift carry "in hand". Auto-scroll itself runs.
- **5b's "paper rustle on drop"** — the Sound Catalog (Settings 3a) has no drop event; adding one is a sound-design call.
- **3a's in-app edge-swipe pop / 2b's swipe-down** — the OS back gesture already pops (and plays 3a); an in-app edge swipe would fight Android's.
- **Today / Routines / Paper drags moved onto the kit** — not my folders. They're one-swap candidates: `DragRow` + `DropZone` + their own `verdict`/`drop` (see the Today note below).
