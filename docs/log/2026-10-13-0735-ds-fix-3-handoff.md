## When a literal counts as "exactly equal"

Most size and tracking tokens change at 767px (`typography.css`). For example, `--fs-caption` is 12.5 on desktop and 13 on a phone. A literal therefore qualifies only in one of these cases:

1. **The token is the same at both widths:** `--fs-body-l` 16, `--ls-display` −0.015em, `--acc-blossom-text` (see the colour item below).
2. **The line renders on one side of 767px only,** and the literal equals the token's value there. "One side" means:
   - a branch on the kit `useIsMobile()` (`(max-width: 767px)`, the same breakpoint as the tokens), such as the phone/desktop early returns in Projects and People, `!isMobile &&` in Routines, or the phone-only streak count;
   - the Library three-pane branch, because its own hook only returns false above 767px.

   Library's *single-column* branch also renders on a narrow desktop page, so it only got the swaps that hold on both sides.
3. **A phone rule already overrides the property, so only the desktop value is ever drawn:**
   - `.app-shell [style*="uppercase"] { letter-spacing: 0.07em !important }` covers every inline uppercase label. Tracking of 0.12/0.18/0.22em there became `--ls-mono-tight`/`--ls-mono`/`--ls-mono-wide`. This only applies inside `.app-shell`; BottomSheet and Float portal to `<body>`, so nothing inside them was swapped this way.
   - `.app-main-content h1 { font-size: 26px !important }` covers page titles. The Herbarium title (44) became `--fs-page-title`, and the Library book title (22) became `--fs-display-m`.
4. **Role must match:**
   - Caveat text only takes `--fs-hand*`.
   - `--fs-mono-*` only goes on mono text.
   - `--fs-badge` and `--fs-tab-label` (12 at both widths) were **not** used for ordinary 12px text. That would hide drift behind a token with another job.
5. **Colour must match in both themes.** One case qualified:
   - Tasks domain chips: `var(--kf-chip-tasks, #8A4A58)` → `var(--acc-blossom-text)`. The old pair resolved to #8A4A58 by day (fallback) and #E9BFC5 at night (`index.css:152`), which are exactly the token's two values.
   - No other in-scope colour equals a token in both themes. See the left-alone list.

## Left alone, and why

- **Sizes that match a token at one width only.** These are 12.5, 13, 13.5, 14, 15, 17, 18 and 22 in code drawn at both widths. For example, 12.5 is `--fs-caption` on desktop but the phone caption is 13. Swapping would resize the phone (or the desktop). This is the bulk of what remains and is the actual design decision: does the phone grow to the refreshed scale here?
- **Caveat 16 in shared code** (Focus garden ×7, Project detail ×2). `--fs-hand` is 16 on desktop but 18 on a phone. `--fs-body-l` would match by value, but that hides a hand line behind a body token.
- **12px text** (Library ×26 and others) only equals `--fs-badge`/`--fs-tab-label`, which are role tokens.
- **11px UI text** (not mono) only equals `--fs-mono-l`.
- **Tracking in CSS-class rules shared by both widths:** Herbarium `.ledger` 0.12em, `.seas span.t` 0.22em. The phone uppercase override only covers inline styles, so these would change on a phone.
- **Colours with no both-theme token:**
  - Focus garden/dusk inks are the old night values (`#8e88a0`, `#5f5a6e`, `#e4ddcc`, …). `#f0ebdd`/`#c9c0d8`/`rgba(240,235,221,.14)` equal *night-only* tokens, and the garden isn't scoped night, so the day render would flip. The audit's fix (`data-theme="night"` on the garden) is a restyle, not a swap.
  - `rgba(201,165,90,α)` is `--acc-gold-warm` at an alpha; no alpha token exists.
  - The petal gradient `#E8C4CC → #D4A8B0` is day `--acc-blossom` only.
  - The washi `rgba(255,255,255,.3)`, Routines `#4a3a1e`, and the Herbarium `var(--sky-horizon,#8b7a5e)` day fallback have no token.
- **User palette data:** `#7a4a52`, `#8b8471` in NewProjectModal and ProjectDetailPage are stored swatches (the audit says they are acceptable).
- **Ternaries with an off-scale arm,** such as `isMobile ? 24 : 40` and `compact ? 11 : 12.5`. Tokenising one arm leaves the hit.
- **All radii:** a flagged radius is off-scale by definition.

Two things I noticed, out of scope:
- `var(--kf-chip-tasks, #8A4A58)` is still used once in `tasks/TaskRow.tsx:327`. The same swap there would let `index.css:152` drop `--kf-chip-tasks` (audit #26).
- The phone h1 rule makes every per-page phone title literal dead. For example, Weekly review's `isMobile ? 24` never draws, because 26 wins.
