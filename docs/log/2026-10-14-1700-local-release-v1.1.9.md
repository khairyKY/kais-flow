# v1.1.9: saves that leave sooner

Rollback point: v1.1.8 on master (`bca255ce`).

## What's in it
- **Root cause:** every outbox step fired `kf-outbox-change`, and `useOutboxMarks` answered each one with new Sets, so CalendarPage, PhoneCalendar, TodayPage and TaskSheet re-rendered on every enqueue/peek/remove. The queue's next IndexedDB step waited behind each render. `getSession` was 0 ms in every trace, so it wasn't the cause.
- **Fix:** `outboxMarks()` keeps the previous identity when the ids are unchanged, and `withQueue` doesn't write back an unchanged peek. Ordering, retry/backoff, persistence, the account check and dead-lettering are untouched.
- **Production build, mock backend, median of 7 runs:**
  - slot drop: 687/1252 ms → 282/431 ms (first send / drained);
  - complete a slot task: 328/442 → 132/192 ms.

## Evidence
- vitest 2,221, with 2 new outbox tests (red before, green after); lint 0.
- Harnesses: time-slots 52 · event-detail 68 · cal-wave2 83 · today-shell 88 · fix-tasks 70 · cal-rail-drop 33.
