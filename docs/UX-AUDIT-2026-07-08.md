# UX Audit — 2026-07-08

Full hands-on audit of the live dev build (branch `feature/day-count-views-50`): signed in, clicked and typed through all 9 routes, every menu, the command bar, search, chat, keyboard shortcuts, and the mobile viewport. Console stayed clean the entire session.

**Verdict:** the foundation is solid, but the experience layer is not "second nature" yet. The app repeatedly **swallows actions silently**, **hides its own features**, and **disagrees with itself about what things are called**.

Each finding below is filed as a GitHub issue (`ux-audit` label). Priorities: **P0** = broken, **P1** = core-UX blockers, **P2** = friction/trust, **P3** = under the hood.

---

## P0 — Actually broken

### 1. Settings page is unreachable + `app_settings` 406 kills the day-count feature
- No link anywhere navigates to `/settings`. The sidebar "Settings" button only opens the terrarium popover (`AppLayout.tsx:541`).
- Even at the URL directly, the Calendar card silently vanishes: `app/src/lib/settings.ts:11` uses `.single()` and the user has no `app_settings` row → PostgREST **406** (observed 3 failed requests). `CalendarPage` then always falls back to 7 days.
- Net effect: **feature #50 (custom day-count views) is completely invisible in production.**
- Fix: `.maybeSingle()` + seed/upsert a default row; add a Settings nav link; move the 1/3/5/7/14-day switcher onto the calendar toolbar.

### 2. Calendar right-click menu items are stubs
- Both "New Event" and "New Time Block" do nothing but close the menu: `onClick: () => { setContextMenu(null) }` (`CalendarPage.tsx:140-141`).
- Fix: open the event modal pre-filled with the clicked slot/time, or remove the menu until wired.

### 3. Event edit modal shows UTC, not local (Cairo) time
- An event rendered at Sun 12:00–1:00 AM Cairo opens with date `2026-07-04`, starts `21:00`, ends `22:00` (raw UTC values in the form fields).
- Saving without touching anything shifts the event by 3 hours. **Data corruption on every edit.**

### 4. Activity page renders raw JSON and "Invalid Date"
- The page's only entry: `Routine checked` / `{"date":"2026-07-08"}` / `Invalid Date`.
- Fix: humanize payloads, fix the date parsing.

### 5. Chat leaks internal notation and duplicate sources
- Answer text included `([task] Verify core loop capture, [inbox_item] Verify core loop capture)`.
- Sources list shows the same item twice (task + its inbox twin), unlabeled and unclickable.
- Fix: strip internal tags from responses, dedupe sources, render them as links.

## P1 — "Second nature" blockers

### 6. Actions vanish silently — no toast, no undo (worst pattern in the app)
- Quick-add (Enter): bar closes, nothing confirms. File-as-task: item disappears, no "view task", no undo. Dismiss: gone, no undo, no dismissed-items view. Complete (`e` **or space**): row disappears instantly, no undo.
- There is **no completed-tasks view anywhere**, so a fat-fingered spacebar = task lost from the UI forever.
- The toast store already exists and bulk actions use it (`TasksPage.tsx:379`).
- Fix: toast + 5-second Undo on every single-item mutation; unbind bare space from complete; add a completed/dismissed view.

### 7. Tasks are immutable after creation
- No title editing (clicking a title does nothing), no notes UI, no priority UI, no way to set a specific time. `ScheduleMenu` presets and its date picker all hardcode 9:00 AM (`ScheduleMenu.tsx:100`).
- To fix a typo you must delete and recreate.
- Fix: click-to-edit title + a task detail popover (title, notes, date+time, priority, project).

### 8. Two capture inputs, two grammars; reschedule drops time-of-day
- Ctrl+K parses "tomorrow 3pm"; the Tasks-page "Quick add task…" input does not — "probe two friday 2pm" became a dateless task with that literal title.
- A task created for 3 PM was silently reset to 9 AM by the `1` (today) shortcut.
- Due **times** never render on non-overdue rows, hiding all of this.
- Fix: run `parseCommand` in every capture input; preserve time-of-day on reschedule; show time chips on rows that have one.

### 9. Calendar opens at midnight
- The grid renders all 24h expanded (~2100px) and the page scrolls, so every visit starts at 12 AM.
- Fix: give the grid its own scroller and use FullCalendar `scrollTime` / now indicator positioning.

### 10. Keyboard flows dead-end mid-action
- `s` (snooze) opens the menu but focus stays on the row — arrows/Enter do nothing; you must grab the mouse. Same for the project picker.
- `x` = dismiss in Inbox but select in Tasks — muscle-memory conflict.
- Fix: move focus into popovers and support arrow/Enter; unify `x`.

### 11. One task, five names (taxonomy chaos)
- The same two overdue tasks: "OVERDUE" (Tasks), "Due Today 2" (sidebar), "TODAY" (Planning board), "Nothing here to block" (calendar Today scope).
- A dateless task: "LATER" (Tasks) but "NEXT WEEK" (Planning board).
- Today-page widget "NOTIFICATIONS · 3" vs nav "Activity" page showing "ALL (1)" — different content under swapped names.
- Fix: one taxonomy (Overdue / Today / Tomorrow / This week / Later / Someday) used verbatim everywhere; one name for activity vs notifications.

## P2 — Friction and trust

### 12. Tasks page opens with an admin console
- Domains as always-editable inputs, a merge tool, Areas/Projects CRUD, two adjacent "Add" buttons — all above the actual task list.
- Fix: move to Settings or a collapsed "Manage…" disclosure.

### 13. Morning ritual finishes into a void
- No done-state on the button, no streak feedback after Finish.
- The Top-3 task "PICKED" in step 2 never appears in "TOP 3 FOR TODAY" (it's overdue; the widget only counts today).
- Fix: persist and show ritual completion; Top-3 widget must include overdue starred picks.

### 14. Voice capture is a silent no-op
- Clicked on Today and Inbox: no recording UI, no permission feedback, no error.
- Fix: immediate "requesting mic… / recording" state and error surface.

### 15. Clickability affordances are inverted
- Terrarium cards ("3 letters waiting") look tappable but are pure decoration → make them navigate.
- "PLAN ›" reads as an action button but is a collapse toggle; the actual Planning board isn't in the nav (only reachable from Calendar).
- Complete-checkboxes and stars are bare unlabeled `<span>`s — absent from the accessibility tree, tiny targets; select-box and complete-box sit side-by-side looking near-identical.
- Collapsed sidebar: abstract flower icons with no tooltips.

### 16. Inbox gaps
- No text-capture input on the Inbox page itself (capture only via Ctrl+K — undiscoverable, and unavailable on touch).
- AI says "looks like a **note** · 80%" but the only action is "File as **task**".
- An item whose task already exists still sits in the queue with no "already filed" hint → duplicates.

### 17. Search dead-ends and date-label lies
- Search finds completed tasks (good) but clicking one navigates to /tasks where the item isn't rendered — you land nowhere.
- At 9:46 PM, snooze "Later today" resolves to Thu 12:46 AM and "This evening" to Thu 6 PM — labels lie at night.
- Command-bar date preview is raw `toLocaleString` ("7/9/2026, 3:00:00 PM").

### 18. Mac-only shortcut hints on Windows
- `⌘/` and `⌘J` hardcoded (`AppLayout.tsx:554,564`); also `⌘K`/`⌘/` in CommandBar/SearchOverlay and TasksPage empty-state copy. Kai is on Windows.
- Fix: platform-detect once, render Ctrl on Windows/Linux.

## P3 — Under the hood

### 19. Tasks query ships embeddings to the client
- Every task row carries its full 384-float `embedding` + `search_tsv` (~4KB/task) into the browser. Select explicit columns.

### 20. Remote Google Fonts vs offline PWA
- Fonts load from fonts.gstatic.com; offline typography breaks unless the SW precaches them. Self-host.

### 21. Event modal buttons are all `type="submit"`
- Tabs (EVENT/TIME BLOCK/TASK), ×, and color swatches submit the form — one missing `preventDefault` from surprise saves. Add `type="button"`.

### 22. `window.confirm` for deletes
- Works, but jarring and blocking; once toasts+undo exist (#6), replace confirms with undo.

---

## What's genuinely good — don't break these

- Zero console errors across the whole session.
- Shortcut architecture: single `LIST_SHORTCUTS` source drives both dispatch and the `?` cheatsheet.
- Inbox j/k triage with visible focus rings.
- BulkBar: complete action set, confirms bulk delete, toasts.
- Escape-stack overlay layering never got stuck.
- Mobile: row controls wrap and stay visible instead of hiding behind hover.
- Command bar live parse chips — the best moment in the app.

**Top 5 by impact:** feedback/undo everywhere (#6), editable tasks (#7), settings reachability + 406 fix (#1), calendar opens at now (#9), one taxonomy (#11).
