## Where things are

| What | Where |
|---|---|
| The policies (the text) | `site/src/pages/info.mjs` → the site's `/privacy/` and `/terms/` |
| The app's own copy of the privacy page (Google's OAuth screen needs it on the app's domain) | `app/public/privacy.html`, generated by `site/tools/app-privacy.mjs`, served at the app's `/privacy` |
| **The versions** — the one place | `supabase/functions/_shared/legal.ts`: `TERMS_VERSION`, `PRIVACY_VERSION`, `LEGAL_SUMMARY` |
| Who agreed to what | table `consents` (migration 0083): one row per document version, with `accepted_at` |
| Sign-up's box | `app/src/features/auth/SignInPage.tsx` (the versions go as user metadata; 0083's trigger on `auth.users` writes the rows) |
| The "We've updated our terms" notice | `app/src/features/legal/LegalDialogs.tsx` `TermsNoticeHost`, mounted in `AppLayout` |
| The push + the Activity row about a change | `notify` function, kind `terms` (cron `terms-notice-sweep`, hourly, 0083) |
| Settings → Privacy & terms | `app/src/features/settings/SettingsPage.tsx` `LegalCard` |
| Delete account | Settings → Your data → Delete account (`DeleteAccountRow`) and the notice's "Delete my account" → function `delete-account` |
| Links on sign-in / sign-up | `app/src/features/legal/LegalLinks.tsx` (`openExternal`: a new tab on the web, the system browser in the Windows and Android apps) |

The site and the app can't disagree on a date: the site reads both versions out of `legal.ts` when it
builds (its "updated …" lines), the app and `notify` import the file, and a test
(`app/src/features/legal/legal.test.ts`) fails if `app/public/privacy.html` wasn't regenerated.

## How it behaves

- **Sign up.** Two required boxes (split 2026-10-29, GDPR Art 7(2) / Egypt PDPL): "I agree to the Terms of Use. I’m 16 or older." and "I agree to the Privacy Policy and explicitly consent to keeping sensitive things I choose to write, and to my data being kept in the EU and partly handled in the US." (`ConsentBox` in `features/legal/LegalLinks.tsx`, shared with the notice).
  Create account stays disabled until both are ticked. The ticked versions ride along as sign-up metadata;
  the moment the account is created, the database records them in `consents` (server-side, server time —
  this works with "Confirm email" on, before there's any session).
- **A version bump.** Anyone whose newest agreement is older than the current version (or who has none —
  every account from before 0083) sees a calm card over the app the next time they open it: what changed
  (`LEGAL_SUMMARY`), links to read both, the same box for each document that changed, **I agree** once every box is ticked (writes the new `consents` rows through the outbox; insert-only since 0089),
  and the ways out — Export my data, Delete my account, Sign out. Esc and a tap outside don't close it.
  Offline with nothing cached, it waits rather than block.
- **Outside the app, once per version.** The hourly sweep finds the people who haven't agreed and haven't
  been told under this version, writes one `notify.terms` Activity row each (the "told" mark — written
  before the push, so it never sends twice) and pushes "Our terms changed · Tap to review" to their
  devices. Paused notifications: it waits for the next run. The Android app has no server push (its
  notifications are planned on the phone), so it sees the card when it opens.
- **Email: not built.** There is no $0 email path in the project — the edge functions send none, and
  Supabase Auth's built-in mailer is only for its own sign-up / reset emails (and rate-limited to a few an
  hour). A Gmail App Password over SMTP from an edge function would work but means storing Kai's Gmail
  password as a secret and sending from his personal address; left for Kai to decide.
- **Delete account.** Asks for the word DELETE, offers "Export everything first (.json)". Then: Google
  disconnected (its busy events leave the person's calendar), `delete-account` removes their photos from
  Storage and deletes the auth user with the service role — every table cascades — and the device signs
  out. Works the same on the web, Windows and Android (plain fetches; the export uses `saveFile`, which
  shares on Android).

## Bumping a version (for Kai)

1. Edit the text in `site/src/pages/info.mjs` (privacy, terms, or both).
2. In `supabase/functions/_shared/legal.ts`, set the changed one(s) to today, `YYYY-MM-DD`:
   `TERMS_VERSION` and/or `PRIVACY_VERSION`. Only bump what really changed — a typo fix needs no bump.
3. Rewrite `LEGAL_SUMMARY`: 2–4 short lines saying what changed, in plain words.
4. Rebuild the site and the app's copy:
   `cd site && node build.mjs && node tools/check-links.mjs && node tools/app-privacy.mjs`
5. `cd app && npx vitest run src/features/legal` (fails if step 4's privacy.html is stale).
6. Add a line to the release notes (`site/src/releases.json`) — the policies promise "Field notes says what moved".
7. Release as usual. The release deploys `notify` (with the new versions) and the app: within the hour
   everyone who hasn't agreed gets the push and the Activity row; each person sees the card next time
   they open the app. Redeploy the site too (`cd site && npx wrangler deploy`).
